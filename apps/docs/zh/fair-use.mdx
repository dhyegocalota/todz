---
title: 合理使用
---

todz 可以免费使用。为了避免某一个账户拖垮服务，或让账单超出套餐，每个账户都有下列限制。这些限制很宽松：个人待办清单远远用不到。

## 限制

| 限制 | 默认值 | 超出后会怎样 |
|---|---|---|
| 每个账户的工作区数 | 20 | 创建工作区会被拒绝 |
| 每个工作区的项目数 | 100 | 创建项目会被拒绝 |
| 每个项目的未完成任务数 | 5,000 | 添加或重新打开任务会被拒绝；完成一个任务就会腾出一个名额 |
| 标题 | 500 个字符 | 该任务会被拒绝 |
| 备注 | 20,000 个字符 | 该任务会被拒绝 |
| 每天的任务更改数 | 1,000（按 UTC 日计）| 只统计添加、编辑、完成和重新打开任务，包括通过回复每日邮件添加的任务，其他一概不计（创建工作区或项目不计入）。更改会被拒绝，直到 UTC 午夜；读取仍然可用 |
| 已存储的任务文本 | 50 MB | 写入会被拒绝；读取仍然可用。该计数是上限估算：它按原样累加每个标题、备注和编辑，编辑或删除时不会减少，所以运营方可以为某个账户重置它 |
| 每个网络每天的新账户数 | 5 | 注册会被拒绝，直到第二天 |

被拒绝时，系统会告诉你发生了什么。服务器返回一个代码和一句通俗的话；对智能体来说，工具会返回同样的这句话。

## 一次性邮箱地址

不能用一次性邮件服务的地址开设新账户。现有账户不受影响。

## 暂停账户

如果账户被滥用，运营方可以暂停它。被暂停的账户仍然可以读取自己的任务并退出登录，但不能更改任何内容，它的智能体也会停止响应，直到账户恢复。不会删除任何内容。

## todz cloud 容量

免费的 todz cloud 名额极其有限。todz cloud 按固定的月度预算运行，因此最多接纳 50 个活跃账户。自行托管永远开放：[运行你自己的服务器](/zh/self-host)，不限账户数量。账户在最近 90 天内登录过、被看到处于登录状态或写过任务，即为活跃；闲置 90 天的账户会释放名额，如果它回来时云端已满，会像新地址一样等待名额。

- 已经被接纳的账户绝不会因为这个上限而被拒绝。
- 云端已满时，无论哪个地址请求登录链接，看到的都是一样的：回答始终是链接正在发送途中。不被允许登录的地址会收到一封邮件，写着“todz cloud 目前已满”，并附有一个指向 todz.app/cloud-queue 队列的个人链接，该链接一周内有效，在那里确认地址后，有名额时就会收到邀请，邮件里还有一个指向[自行托管](/zh/self-host)的链接。
- 当本月用量接近套餐包含的额度时，运营方会收到邮件。超过 95% 之后，本月写入最多的账户会被拒绝新的写入，并提示“本月 todz cloud 已达容量上限”（HTTP 429，`Retry-After` 为距下月 1 日 UTC 的秒数），所有人的读取也会降到每分钟寥寥几次。你的任务不会被删除，其余账户照常写入。
- todz cloud 发出的每一封邮件都计入它的月度邮件额度，因此每个地址每天最多收到 10 封邮件。

自行托管的服务器没有账户上限，除非它把 `CLOUD_ACCOUNTS_MAX` 设为正整数。

## 自行托管的服务器

这些数值是 Worker 变量。省略某一项即保留其默认值；设为正整数即可更改：

- `FAIR_USE_WORKSPACES_MAX`
- `FAIR_USE_PROJECTS_PER_WORKSPACE_MAX`
- `FAIR_USE_OPEN_TASKS_PER_PROJECT_MAX`
- `FAIR_USE_WRITES_PER_DAY_MAX`
- `FAIR_USE_STORED_BYTES_MAX`（单位为字节）
- `FAIR_USE_SIGN_UPS_PER_CLIENT_DAY_MAX`

对新账户的上限还需要密钥 `SIGN_UP_KEY_SECRET`（参见[服务器设置](/zh/self-host#6-turnstile)）；没有它，新账户就无法注册。不是正整数的值会让服务器报错停止，错误信息会指出变量名。标题和备注的长度是固定的，因为 App 和智能体工具都会写明它们。
