---
title: Connect an agent
description: Sign Claude Code, Claude.ai, Codex or Cursor in to todz with OAuth, or give them a key to one project.
---

The todz MCP server at `https://api.todz.app/mcp` supports MCP OAuth. Add the URL to your client with no key. The first call opens your browser, and you approve the app there. If your client has no OAuth, use a [project key](#with-a-key-instead) instead.

If you run your own server, use its URL in place of `https://api.todz.app/mcp`.

## Sign in with OAuth

1. Enter your todz email and pass the check.
2. Open the sign-in link from the mail **in the same browser**.
3. Read the consent screen: it names the app and where it sends you back.
4. Pick one project. The first one is preselected. Or pick **Your whole account (owner scope)**, which is never preselected and warns "It can create, rename and delete every workspace and project."
5. Approve, or Deny.

A project grant behaves like a key to that project: the task tools, and the other projects of its workspace for `move` and `projects`. An owner grant behaves like an owner key: the account tools only. The history of a task names the app by the name it registered. See [MCP tools](/mcp-tools).

Access tokens last one hour and renew themselves. Refresh tokens last 30 days and rotate on every use; if one is used twice, the app is disconnected. todz stores tokens only as digests. Fair use and the cloud cap apply exactly as they do for keys.

To disconnect an app, open **Settings** › **Connected apps** in the Mac app, next to **Account keys**, in version 0.2.7 or later. The app stops at once.

Redirect addresses must be `https` or a loopback address (`127.0.0.1`, `localhost`, `[::1]`). Custom schemes are refused, as the specification requires; a client that needs one should use a project key.

### Claude Code

```bash
claude mcp add --transport http todz https://api.todz.app/mcp
```

Then run `/mcp` in Claude Code and choose todz to sign in. Claude Code opens the browser.

### Claude.ai and Claude Desktop

Open **Settings** › **Connectors** › **Add custom connector**, enter `https://api.todz.app/mcp` as the URL, then press **Connect**.

### Codex

Add this to `~/.codex/config.toml`:

```toml
[mcp_servers.todz]
url = "https://api.todz.app/mcp"
```

Then sign in:

```bash
codex mcp login todz
```

### Cursor

Add this to `~/.cursor/mcp.json`:

```json
{ "mcpServers": { "todz": { "url": "https://api.todz.app/mcp" } } }
```

If Cursor's sign-in does not open, or it reports a redirect error, use a project key instead.

## With a key instead

Open **Connect an Agent** in the app's sidebar, pick a project and copy the command of your client: the app creates a key and puts it in the command. A key reaches one project, and you see it once. Project keys and owner keys keep working: they are the fallback for clients without OAuth.

The commands below show `<key>` where the app puts yours. They point at the todz cloud; if you run your own server, the app shows commands with your server instead.

<Warning>
  The key is a password for that project. Never commit it, and keep your agent's configuration at the user level, not in a file inside a repository such as `.cursor/mcp.json` or a command run with `--scope project`. If a key leaks, open **Connect an Agent** and revoke it there.
</Warning>

### Claude Code

Run it in your project's folder:

```bash
claude mcp add --transport http todz 'https://api.todz.app/mcp' --header 'Authorization: Bearer <key>'
```

### Codex

Add this to your Codex configuration:

```toml
[mcp_servers.todz]
url = "https://api.todz.app/mcp"
bearer_token_env_var = "TODZ_API_KEY"
```

Then export the key in the shell that starts Codex:

```bash
export TODZ_API_KEY='<key>'
```

### Cursor

Add this to your user-level Cursor MCP configuration, `~/.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "todz": {
      "url": "https://api.todz.app/mcp",
      "headers": {
        "Authorization": "Bearer <key>"
      }
    }
  }
}
```

The agent now has the [MCP tools](/mcp-tools).
