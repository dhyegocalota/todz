The todz MCP server at `https://api.todz.app/mcp` signs clients in with MCP OAuth. Add the URL to your client. The first call opens your browser, and you approve the app there. OAuth is the only way to connect.

If you run your own server, use its URL in place of `https://api.todz.app/mcp`.

## Breaking change: API keys were removed

On 2026-11-27 todz removed API keys. Project keys and owner keys stopped working, and the server deleted every stored key. A client that still sends a key gets `401` with a pointer to this page.

To reconnect an agent that used a key, run `claude mcp add --transport http todz https://api.todz.app/mcp` and sign in, as below. Remove the old `Authorization` header, and the `TODZ_API_KEY` variable if you set one. The **Connect an Agent** screen of the Mac app is gone in the same update.

## Sign in with OAuth

1. Enter your todz email and pass the check.
2. Open the sign-in link from the mail **in the same browser**.
3. Read the consent screen: it names the app and where it sends you back.
4. Pick one project. The first one is preselected. Or pick **Your whole account (owner scope)**, which is never preselected and warns "It can read and change every task, and create, rename and delete every workspace and project."
5. Approve, or Deny.

A project scope gives the task tools, and the other projects of its workspace for `move` and `projects`. An owner scope gives the account tools and the same task tools for every project of the account, each taking the `project` id from `workspaces`. The history of a task names the app by the name it registered. See [MCP tools](/mcp-tools).

Access tokens last one hour and renew themselves. Refresh tokens last 30 days and rotate on every use; a retry gets a fresh pair until the new token is used, and a spent one used after that disconnects the app. todz stores tokens only as digests. Fair use and the cloud cap apply to every connected app.

To disconnect an app, open **Settings** › **Connected apps** in the Mac app. The app stops at once.

Redirect addresses must be `https` or a loopback address (`127.0.0.1`, `localhost`, `[::1]`). Custom schemes are refused, as the specification requires.

### Claude Code

```bash
claude mcp add --transport http todz https://api.todz.app/mcp
```

Then run `/mcp` in Claude Code and choose todz to sign in. Claude Code opens the browser.

### Claude.ai and Claude Desktop

Open **Settings** › **Connectors** › **Add custom connector**, enter `https://api.todz.app/mcp` as the URL, then press **Connect**.

### Codex

Add this to `~/.codex/config.toml`:

```toml
[mcp_servers.todz]
url = "https://api.todz.app/mcp"
```

Then sign in:

```bash
codex mcp login todz
```

### Cursor

Cursor signs in to MCP servers with a `cursor://` address, which the MCP specification does not allow and todz refuses. Cursor cannot connect to todz until it signs in with an `https` or loopback address.
