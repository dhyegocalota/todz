Run your own todz server on Cloudflare and point the macOS app and your agents at it. The server is one Worker with a D1 database and one Durable Object per project.

Paste this into your coding agent. It does the whole setup and stops only to ask you for a login, a payment or a secret.

```text
Self-host todz: follow https://raw.githubusercontent.com/dhyegocalota/todz/main/docs/runbooks/self-host-with-an-agent.md end to end on my Cloudflare account, and stop only to ask me for logins, payments and secrets.
```

<Accordion title="Do it by hand">

## What you need

- A Cloudflare account on **Workers Paid** (the email binding needs it) and a domain in that account. Below, `example.com` stands for it and `api.example.com` for the server.
- Node and pnpm, in the versions of `.nvmrc` and `package.json`, and a Mac with Xcode and XcodeGen for the app.
- Wrangler logged in to your account: `pnpm --filter @todz/api exec wrangler login`.

## 1. Fork, install and check

Fork the repository, then, before renaming anything:

```bash
pnpm install
pnpm verify all
```

The gate also needs gitleaks; its doctor names anything missing. Run it now, because some tests pin todz's own production names, for example the checks of the API source and of the email sender. After step 2 those pins fail until you update them to your names.

## 2. Rename

Edit `apps/api/wrangler.jsonc`:

- `account_id`: your account's id.
- `routes`: replace `api.todz.app`, `todz.app` and `www.todz.app` with `api.example.com`, `example.com` and `www.example.com`, keeping `custom_domain` `true`.
- `vars.PUBLIC_ORIGIN`: `https://api.example.com`.
- `vars.SITE_ORIGIN`: `https://example.com`, where the landing page and this guide are served.
- `send_email[0].allowed_sender_addresses`: your sender, for example `noreply@example.com`.
- `vars.TELEMETRY`: delete this line. A fork inherits `on` from this file, so removing it is what turns telemetry off; it is off unless the value is exactly `on` (see the Privacy page).
- `vars.CLOUD_ACCOUNTS_MAX`: delete this line. A fork inherits todz cloud's account cap from this file; without it your server admits every account (see the Fair use page).
- `ratelimits`: keep the twenty bindings, four for sign-in (one of them for emailed-code attempts), three for the admin, one for replies to the day email, one for its stop link, one for signed-in owners, one for MCP clients, three for the usage report, two for the update check, one for reads at capacity and three for OAuth (its routes, and client registration per client and in total); change each `namespace_id` if your account already uses `8601` to `8620`.

Keep the rest as it is. In particular, `vars.SIGN_IN_PROVIDER` stays `email`, `vars.EMAIL_SENDER` stays `cloudflare`, and `workers_dev` and `preview_urls` stay `false`. Never pass `--var` to `wrangler deploy`, and never set variables in the dashboard: a fake provider, or a sender that only logs the link, opens sign-in to anyone.

In `apps/api/src/email-sender.ts`, set `SENDER_ADDRESS` and `REPLY_TO_ADDRESS` to your own addresses.

## 3. Create the database and apply the migrations

```bash
pnpm --filter @todz/api exec wrangler d1 create todz-directory
```

Put the printed id in `d1_databases[0].database_id`, then:

```bash
pnpm --filter @todz/api exec wrangler d1 migrations apply todz-directory --remote
```

## 4. Deploy

```bash
pnpm --filter @todz/api server:deploy
```

Deploy from a git clone: the script names the build after the commit it reads with `git log`. When the deploy succeeds, the script ends with `todz server ready: https://api.example.com · server 2026.11.25+3f9c2ab · accepts app 0.2.4 or later  →  paste it in todz › Settings › Server`: that is the URL step 7 uses, with the server's own version and the oldest app version it accepts. Cloudflare creates the DNS records and the certificates for `api.example.com`, `example.com` and `www.example.com`; none of the three may already have an A, AAAA or CNAME record. Check four things:
- `curl -sS -H "Todz-App-Version: 0.2.4" https://api.example.com/owner/sign-in-method` answers `{"method":"link"}`, and the same request without the header answers `{"error":"app_too_old","minimum_app_version":"0.2.4"}`;
- `curl -sS https://api.example.com/health` answers `{"service":"todz","origin":"https://api.example.com","version":"2026.11.25+3f9c2ab","minimum_app_version":"0.2.4"}`, and its `version` is the one the ready line printed;
- the account's `todz-api.<subdomain>.workers.dev` address does not answer;
- until step 6 is done, sending a link answers 503 `sign_in_unavailable`, which is the safe state.

## 5. Email sending

Enable sending for your domain and add the records Cloudflare lists. The zone id is on the domain's Overview page in the dashboard.

```bash
pnpm --filter @todz/api exec wrangler email sending enable example.com --zone-id <your zone id>
pnpm --filter @todz/api exec wrangler email sending dns get example.com --zone-id <your zone id>
```

## 6. Turnstile

Sign-in and the admin stay closed (`sign_in_unavailable` and "The admin is closed right now.") until Turnstile is set up. In the Cloudflare dashboard, create a Turnstile widget for `example.com` in Managed mode. Put its site key in `vars.TURNSTILE_SITE_KEY` in `apps/api/wrangler.jsonc`, deploy again with `pnpm --filter @todz/api server:deploy`, and store its secret:

```bash
pnpm --filter @todz/api exec wrangler secret put TURNSTILE_SECRET_KEY
```

Wrangler asks for the value, which keeps it out of your shell history. Never pipe it in, never export it, and never write it into `wrangler.jsonc`.

The admin at `https://example.com/admin`, where you read the metrics of your server, signs in only the address you store the same way; until you do, it stays closed:

```bash
pnpm --filter @todz/api exec wrangler secret put ADMIN_EMAIL
```

New accounts are capped per network per day (see [Fair use](https://docs.todz.app/fair-use)), and the cap keys each address with a secret. Generate it once and store it the same way; until you do, new accounts cannot sign up and existing ones still can:

```bash
openssl rand -hex 32 | pnpm --filter @todz/api exec wrangler secret put SIGN_UP_KEY_SECRET
```

## 7. Build the macOS app and point it at your server

In `apps/macos/project.yml`:
- in both targets, replace `DEVELOPMENT_TEAM` with your own team's id (Xcode → Settings → Accounts; the free Personal Team works);
- replace `bundleIdPrefix`, the `TODZ_APP_BUNDLE_IDENTIFIER` and `TODZ_WIDGETS_BUNDLE_IDENTIFIER` values and `TODZ_APP_GROUP` with identifiers of your own.

Then build:

```bash
xcodegen generate --spec apps/macos/project.yml
xcodebuild build -project apps/macos/Todz.xcodeproj -scheme Todz -configuration Release -derivedDataPath apps/macos/build
```

Your Release app opens sign-in links on `todz`, and the server needs no setting for it, because the app names its scheme when it asks for a link.

Then open todz › Settings › Server and paste the URL the deploy printed. The app checks it, signs out of the server it was on and starts clean on yours. Sign in with your email.

## 8. Point an MCP client at your server

Clients that speak MCP OAuth connect with the address alone, and you approve them in the browser:

```bash
claude mcp add --transport http todz https://api.example.com/mcp
```

Your server is its own OAuth authorization server: the issuer is `PUBLIC_ORIGIN`, so its metadata lives at `https://api.example.com/.well-known/oauth-authorization-server` and the sign-in mails come from your sender. Nothing else needs configuring, but OAuth sign-in needs steps 5 and 6, like the app's.

OAuth is the only way a client connects, on your server as on todz cloud. A client that sends any other credential gets a 401 that points to the connect page of the docs.

## Updating

Pull from upstream. Update the server first, then the app: an app newer than its server cannot check the server's address. Run:

```bash
pnpm --filter @todz/api exec wrangler d1 migrations apply todz-directory --remote
pnpm --filter @todz/api server:deploy
```

Then build the app again as in step 7; it keeps the server you pasted.

On a server that already has owners, an owner who never touched Email me my day gets it only after you turn that default on for them by hand, which is safe once no such owner would be mailed; new owners get it at once.

Migrations only move forward. Never roll back to a version from before the sign-in guard, whether with `wrangler rollback` or the dashboard's Deployments page. To close sign-in, delete the secret:

```bash
pnpm --filter @todz/api exec wrangler secret delete TURNSTILE_SECRET_KEY
```

## App updates

- The official app from todz.app updates itself from todz.app's signed appcast, even when it points at your server: the server you choose and the app's updates are independent. See [Install on Mac › Updates](https://docs.todz.app/install-on-mac#4-updates).
- An app you built yourself, as in step 7, never installs an update by itself; it may offer the official one, which replaces your build. To keep your own build, build it again as above, or install the official app and paste your server under **Server**.
- Keep your server current. When a new app needs a newer server, the app says the server is older; update the server first.
