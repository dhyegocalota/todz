---
title: フェアユース
---

todzは無料でお使いいただけます。1つのアカウントがサービスを停止させたり、料金をプランの範囲外に押し上げたりしないよう、すべてのアカウントに以下の上限があります。上限には余裕があり、個人用のToDoリストが近づくことはありません。

## 上限

| 上限 | デフォルト | 上限を超えると |
|---|---|---|
| アカウントあたりのワークスペース | 20 | ワークスペースを作成できません |
| ワークスペースあたりのプロジェクト | 100 | プロジェクトを作成できません |
| プロジェクトあたりの未完了のタスク | 5,000 | タスクの追加と再オープンができません。タスクを完了すると枠が空きます |
| タイトル | 500文字 | タスクが受け付けられません |
| メモ | 20,000文字 | タスクが受け付けられません |
| 1日あたりのタスクの変更 | 1,000（UTCの1日） | タスクの追加、編集、完了、再オープンを数えます（その日のメールへの返信で追加したタスクも含みます）。ほかは数えません（ワークスペースやプロジェクトの作成は数えません）。変更はUTCの午前0時まで受け付けられず、読み取りは引き続き使えます |
| 保存されるタスクのテキスト | 50 MB | 書き込みが受け付けられず、読み取りは引き続き使えます。この数値は上限の目安です。タイトル、メモ、編集を書かれたとおりにすべて加算し、編集や削除をしても減らないため、運営者がアカウントごとにリセットできます |
| 1日あたりのネットワークごとの新規アカウント | 5 | 翌日まで登録できません |

受け付けられなかった場合は、何が起きたかをお知らせします。サーバはコードと分かりやすい一文で応答し、エージェントにはツールが同じ一文で応答します。

## 使い捨てメールアドレス

使い捨てメールサービスのアドレスでは、新規アカウントを開設できません。既存のアカウントには影響しません。

## 停止措置

アカウントが悪用された場合、運営者はそのアカウントを停止できます。停止されたアカウントは、タスクの読み取りとサインアウトはできますが、何も変更できず、そのエージェントはアカウントが復旧するまで応答しなくなります。削除されるものはありません。

## todz cloudの容量

無料のtodz cloudの枠は非常に限られています。todz cloudは月々固定の予算で動いているため、受け入れるアクティブなアカウントは最大50件です。セルフホストはいつでも利用できます。アカウントの上限なしで[独自のサーバを動かせます](/ja/self-host)。アカウントがアクティブとは、過去90日以内にサインインした、サインイン中として確認された、またはタスクを書き込んだ状態をいいます。90日間アイドルのままのアカウントは枠を手放し、戻ってきたときにクラウドが満員であれば、新しいアドレスと同じように枠が空くのを待ちます。

- すでに受け入れられたアカウントが、上限を理由に拒否されることはありません。
- クラウドが満員のとき、サインインリンクのリクエストはどのアドレスでも同じ見え方になります。応答は常に、リンクを送信中という内容です。サインインできないアドレスには、「todz cloudはただいま満員です」というメールが届きます。このメールには、todz.app/cloud-queueの順番待ちへの個別リンク（1週間有効で、そこでアドレスを確認すると、枠が空いたときに招待されます）と、[セルフホスト](/ja/self-host)へのリンクが含まれます。
- その月の使用量がプランに含まれる割り当てに近づくと、運営者にメールが送られます。95%を超えると、その月の書き込みが最も多いアカウントには、新しい書き込みが「todz cloudは今月、容量の上限に達しています」（HTTP 429、`Retry-After`には翌月1日（UTC）までの秒数）として拒否され、全員の読み取りは1分あたり数回に制限されます。タスクが削除されることはなく、ほかのアカウントはいつもどおり書き込みを続けられます。
- todz cloudが送るメールはすべて月間のメール送信枠にカウントされるため、1つのアドレスに送られるメールは1日10通までです。

セルフホストのサーバには、`CLOUD_ACCOUNTS_MAX`に正の整数を設定しない限り、アカウントの上限はありません。

## セルフホストのサーバ

数値はWorkerの変数です。省略するとデフォルトのままになり、正の整数を設定すると変更できます。

- `FAIR_USE_WORKSPACES_MAX`
- `FAIR_USE_PROJECTS_PER_WORKSPACE_MAX`
- `FAIR_USE_OPEN_TASKS_PER_PROJECT_MAX`
- `FAIR_USE_WRITES_PER_DAY_MAX`
- `FAIR_USE_STORED_BYTES_MAX`（バイト単位）
- `FAIR_USE_SIGN_UPS_PER_CLIENT_DAY_MAX`

新規アカウントの上限には、シークレット`SIGN_UP_KEY_SECRET`も必要です（[サーバのセットアップ](/ja/self-host#6-turnstile)をご覧ください）。これがないと、新規アカウントは登録できません。正の整数ではない値を設定すると、その変数名を示すエラーとともにサーバが停止します。タイトルとメモのサイズは固定です。アプリとエージェントのツールがその値を明示しているためです。
