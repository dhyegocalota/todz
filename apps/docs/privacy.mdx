---
title: Privacy
description: Exactly what todz counts, what it never stores, and how to turn it off.
---

todz counts how it is used in daily totals. It never stores a log of what anyone did, and it never reads your tasks to do it.

## What is counted

Each count is one number for one day, with at most one short label.

| Count | Where it comes from | Label |
| --- | --- | --- |
| Owners, workspaces, projects | The server's own records, once a night | none |
| Tasks added, tasks completed | A count from each project, once a night | none |
| Agent writes | A count of what agents changed, once a night | the agent's name from a fixed list (Claude Code, Codex, Cursor, Gemini, Windsurf, Zed, VS Code), anything else as `other` |
| Day mails sent | The server's own records, once a night | none |
| Update checks | The Mac app asking for updates | the app version and the macOS major version, such as `0.2.1\|15` |
| Shared usage reports | The Mac app, only if you turn on **Share anonymous usage** | the app version and the macOS major version |
| Shared usage events | The same report | one of `popover_opened`, `day_closed`, `morning_glance`, `shortcut_used`, `multi_workspace` |

## What is never stored

- No task title, note, project name, workspace name or email address.
- No IP address and no user agent. An update check's user agent is read for the two version numbers and dropped.
- No log of events and no timestamp of any single event. Only a day and a total.
- The random code the Mac app sends with a report changes every 30 days, is used only to slow down abuse and is never stored.

Totals are kept for 13 months and then deleted by the server.

## Share anonymous usage

The Mac app asks once. It is off until you say yes, and you can change it any time in Settings. When on, the app keeps a count of the five events above on your Mac and sends one small report a day: counts, the app version, the macOS major version and the random code. A report is under 1 KB, and the server refuses anything over 2 KB.

## Self-hosting

A server you run counts nothing. The setting `TELEMETRY` is off unless it is set to exactly `on`, and the self-host guide has you remove it. A Mac app signed in to your server sends its report to your server, which refuses it.

## Where the numbers are read

Only the owner of the hosted service reads them, on a signed-in admin page with a CSV export. The code is open: see `apps/api/src/telemetry` in the repository.
