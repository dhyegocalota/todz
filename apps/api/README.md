# @todz/api

The Worker behind the MCP server and the owner API. A directory knows who owns which workspace and project and which credential opens which project; each project keeps its tasks and their history in a store of its own. A credential reaches a project only through the directory, so no read or write ever crosses a project boundary. It applies the shared task rules in a single transaction and answers expected failures with results.

The MCP server lets an agent in any MCP client read and change the tasks of one project with one key, shown once and kept only as a digest. It speaks both protocol eras, names the client behind every write, sees today in the owner's time zone, and answers in compact text with short task ids, never naming another project. Unless the owner turns it off, the next task comes with one line saying how many of the project's tasks are due today or overdue.

The owner signs in with a link sent to their email address: the link works once, for a few minutes, and only in the app that asked for it. A development Worker prints the message in its console instead of mailing it; a deployed one mails it from todz through Cloudflare, as a designed message with a plain-text twin, and welcomes an owner once, when the first sign-in creates them. The messages are written as React Email templates and rendered ahead of time, so the Worker carries only their output and serves the logo they show. Every public sign-in route is limited per client address, and both sign-in posts need a solved Cloudflare Turnstile check before they count against a per-address and a global limit, so neither one client nor many can flood the service or mail strangers; a missing piece closes sign-in instead of opening it. The app solves the check for a link request in a small page the Worker serves, and the page the mail opens solves it for the sign-in.

The owner API lets the person behind the agents sign in, keep their workspaces and projects, do everything to a task that an agent can, read a task's history, and issue and revoke the keys that agents use. Each project tells its owner what changed since their last pull and, while the app is open, says only that something changed. Another owner's workspace, project or key is indistinguishable from one that never existed. An owner keeps a bounded number of workspaces, projects in each and live keys in each project, and each session and each key is limited in how fast it calls the Worker, so no tenant can fill the directory every tenant shares.

The same Worker serves the todz website on its own host: one short page that says what todz is, with real screenshots of the app and its download, linking the self-host guide on the docs site; the guide's old address on either host sends visitors there. Every page's footer credits Logic Bit, the studio that built todz. The site host also serves the Mac app's downloads: the disk image of each of the latest two releases with its checksum and signature, and the update feed the app reads. They are static files staged beside the site's own at deploy time, never read from the repository, and the landing always offers the download. Each host answers only its own pages, the www host sends visitors to the site, and any other host finds nothing.

The site describes itself to what reads it other than a person: a search engine, a chat preview, an answer engine or a browser agent. Every public page carries its own title, canonical address, share card, icons and structured data; the site serves its robots rules, sitemap, plain-text guides for language models, web manifest and catalog of agent resources from the same copy as the landing; the MCP server publishes a card describing itself without a key; and the landing offers a browser agent three read-only tools.

The site also holds a small admin for the one owner address: a link mailed to it works only in the browser that asked for it, once and briefly, and opens a short session that shows the metrics of the server and exports them. Every other address gets the same answer and no mail, and the admin is guarded and closes the same way.

When the server is configured with an account cap, only a limited number of active accounts are admitted: every address that asks for a link gets the same answer, one that may not sign in is mailed a way onto a list the admin works through, and a monthly budget guard reads the month's real usage when it can, warns the owner and holds back the heaviest accounts before an included quota runs out. Such a server also counts the mail it sends.

An owner who never turned it off gets a short mail of Today once a day at the time they pick, in their own time zone, never twice for one day, and every mail carries a link that stops it in one click without signing in. Replying to it from the owner's own mailbox adds one task, the reply's first line, to the Inbox of their first workspace, due today; a reply from anyone else, or one that cannot be proven to come from that mailbox, adds nothing and is answered by nothing. No address of todz can be an owner.

On every host the Worker names its own origin, its build version and the oldest app version it accepts at a public health address, so an app can check an address before it uses one; the day mail's stop link is a public address on the API host too, limited per client and answering a page that nothing may index or store. The owner API turns away an app that is too old or does not say its version, with a plain refusal that says to update.

The deployed Worker is production on its own domain, with its own database and the mail sender of todz; a development Worker overrides that configuration and keeps its state on this machine. The development database has a new name since the Worker was first deployed, so state from earlier local runs stays behind and can be deleted.
