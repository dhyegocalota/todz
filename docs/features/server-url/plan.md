# Plan: Server URL

**Spec:** spec.md (design: design.md, every option picked as its recommendation, § 6)
**Tier:** 🔴
**Seam:** a stored server address in TodzKit (`ServerAddress`, `ServerPreference`) that `AppModel` reads and switches through an injected `ServerConnectionFactory`, which rebuilds the owner service and the change socket; the API answers `/health` on its host; a deploy script prints the URL to paste into Settings
**Assumptions (decided, owner can override):**
- The build loop picked every design recommendation (O1 A, O2 A, O3 A, O4 A, O5 B, O6 B, O7 A, O8 A); design.md § 6 records it.
- A stored address with a path other than `/` is refused (`hasPath`). The spec names query, fragment and credentials only; a path would send every request to a route the Worker never serves, so it is refused with a reason.
- Timeouts are constants in one TodzKit file: the probe uses the owner API's request timeout; the sign-out at the old server gives up after 3 seconds, so `Switching…` never waits a minute on an unreachable old server.
- "Use todz cloud" clears the stored address, so the default (the build's `TODZ_API_BASE_URL`) applies again, `localhost:8787` in Debug.
- `/health` must be listed in `assets.run_worker_first` in `apps/api/wrangler.jsonc`, or the static assets answer it first. The spec does not say this; the research found it. The `run_worker_first` pin in `tools/repository-shape/src/api-source.test.ts` changes with it.
- `/health` answers GET only. Any other method, a trailing slash, and a Worker without `PUBLIC_ORIGIN` get the existing empty 404 (`noRouteResponse`).
- The ready line is printed by a script run after `wrangler deploy` succeeds (`&&`), so a failed deploy prints nothing.
- The runbook's production step 8 keeps calling `wrangler deploy` directly: `runbooks.test.ts` requires every wrangler call of the deploy runbook to go through the wrapper.
- `docs/self-host.md` is rendered into `apps/api/src/site/generated/self-host-html.ts`. Regenerating it is part of Lane S's green step, because `generated-site.test.ts` pins it.
- Release's `NSAllowsLocalNetworking` is assumed to let `http://localhost:<port>` and `http://127.0.0.1:<port>` through App Transport Security. ADR 0056 claims it; nothing in the repository proves it. Step A4 and the walk prove it, and the failure mode table names the backout.

## Global Constraints

- An address is `https://` with a host, or `http://` only for `localhost`, `127.0.0.1` or `[::1]` (ADR 0056 § 3). A trailing slash is dropped. No query, fragment, credentials or path.
- The probe is `GET <url>/health`. It must answer `{"service":"todz","origin":"<PUBLIC_ORIGIN>"}` with `cache-control: no-store`. The origin must equal the address typed.
- The switch order is: sign out at the old server (best effort, 3 seconds), erase the session, the cache with its outbox, the widget snapshot, the pending sign-in link and the sign-in method, rebuild the owner service and the change socket, and store the address last. An erase failure stops the switch before the rebuild.
- The ready line is exactly `todz server ready: <PUBLIC_ORIGIN>  →  paste it in todz › Settings › Server`, with two spaces on each side of `→`.
- Copy lives in `*Copy.swift` files. Enums over string literals. Magic numbers at the top of their file. No `??` that masks a missing value. No comments. No acronyms in identifiers. No `.js` extensions in imports. No `sleep`.
- Script names avoid pnpm built-ins (`server:deploy`, never `deploy`; learning 2026-10-17).

## Review Focus

1. An address with surrounding whitespace or an upper-case host, `" https://Todz.Example.com/ "`: accepted as the origin `https://todz.example.com`. Pinned by `ServerAddressTests` in step A1.
2. A probe that answers 200 with HTML, or 404 from a site host: `notTodz`, the switch does not start, the message is "No todz server answered at that address.". Pinned by `OwnerAPIHealthTests` in step A3 and by the walk.
3. A probe that answers todz with another origin, such as `127.0.0.1` typed for a Worker whose `PUBLIC_ORIGIN` is `http://localhost:8787`: refused with the origin named (`answersAs`). Pinned by `ServerProbeOutcomeTests` in step A3 and by the walk.
4. The old server unreachable when signing out, or the erase failing: sign-out failure is ignored and the switch goes on; an erase failure keeps the old server and shows the error. Pinned by `AppModelTests+Server` in step A5.
5. The app quits mid-switch: the address is stored last, so the next launch is on the old server, signed out with its data erased. Pinned by the call-order test in step A5.

## Failure modes

| Step | What breaks | How I notice (the concrete signal) | How I back out |
|------|-------------|------------------------------------|----------------|
| S2 | `/health` answered by the static assets, not the Worker | `curl https://api.todz.app/health` returns the landing's 404 HTML, or the `run_worker_first` pin in Step S1 fails | revert the `run_worker_first` line in `wrangler.jsonc`; the app's probe then refuses every address, so no switch starts |
| S2 | `/health` answers on the site host | the site-host test of Step S1 turns from 404 to 200 | remove the `ROUTE_OF_PATH` entry; `hostKindOf` already separates the hosts |
| S4 | the guide and the generated page disagree | `generated-site.test.ts` and `site:check` fail | run `pnpm --filter @todz/api site:generate` again from the same commit |
| S4 | the script prints the ready line after a failed deploy | the ready line appears above a wrangler error | `&&` in `server:deploy`; the `ready.ts` test pins the order; revert the script entry to `wrangler deploy` |
| S4 | the guide names `server:deploy` but pnpm runs a built-in | the guide's command prints pnpm's usage text instead of deploying | the name is `server:deploy`, not `deploy`; `self-host.test.ts` runs the guide's command names against `package.json` |
| A2 | an address with a path is accepted | `ServerAddressTests` case `https://example.com/todz` returns `.accepted` | the `hasPath` check; the test is the signal |
| A4 | Release ATS blocks `http://localhost:8791` | in the Release walk, the probe fails with an App Transport Security message, not the Worker's answer | stop and ask the owner: keep `TODZ_ALLOWS_LOCAL_NETWORKING` `"NO"` in Release (a Release app then reaches only https servers, which ADR 0056 § 3 must say) or accept another way to reach loopback; the Human checklist covers a real https server either way |
| A5 | the address is stored before the erase | the call-order test fails; a crash in the walk leaves the new address with old data | move the store to the end of `switchServer`; the order test is the pin |
| A6 | the old change watch keeps running after a switch | after a switch the sign-in screen gets an event from the old Worker's socket in the walk | cancel the stored watch task in `switchServer`; the `AppModelTests+Server` cancel test is the pin |
| A6 | extracting `eraseLocalData()` changes what `signOut()` erases | existing `AppModelTests+Owners` or `AppModelTests+Cache` tests go red | revert the extraction and call the erase steps from `switchServer` directly; the duplicate is acceptable and named in the review |
| A7 | a switch from Settings leaves the sign-in screen's method stale | the sign-in screen shows `Getting ready…` after a switch | `.task(id: model.serverAddress)` in Step A8; the walk checks the screen after a switch |
| A8 | the disclosure's form is clipped at 760 by 480 | the walk's narrow-window capture cuts the footnote | stop and ask the owner before changing the layout; O3 A is the picked position, so a fix that moves the line is an owner decision; the walk's screenshot is the signal |
