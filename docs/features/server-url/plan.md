# Plan: Server URL

**Spec:** spec.md (design: design.md, every option picked as its recommendation, § 6)
**Tier:** 🔴
**Seam:** a stored server address in TodzKit (`ServerAddress`, `ServerPreference`) that `AppModel` reads as `serverURL` and switches through an injected `ServerConnectionFactory`, which rebuilds the owner service and the change socket; the Worker answers `/health` on every host; a deploy script prints the URL to paste into Settings
**Assumptions (decided, owner can override):**
- The build loop picked every design recommendation (O1 A, O2 A, O3 A, O4 A, O5 B, O6 B, O7 A, O8 A); design.md § 6 records it.
- A stored address with a path is refused (`hasPath`), and the scheme's default port is dropped from the origin (ADR 0056 § 3). The spec names query, fragment and credentials only; these two are the loop's calls and the owner may overturn them.
- The probe's timeout is 10 seconds, set on the request (`timeoutInterval`) from one named constant in `ServerTiming`. The sign-out at the old server is detached and has no time limit, because nothing waits for it.
- "Use todz cloud" switches without a probe and clears the stored address, so the build's default (`TODZ_API_BASE_URL`, `localhost:8787` in Debug) applies again.
- `/health` is handled in `fetch` before `hostKindOf`, on every host, answering the API origin (ADR 0056 § 4 and § 7). It must also be listed in `assets.run_worker_first` in `apps/api/wrangler.jsonc`, or the static assets answer it first. `api-source.test.ts` pins that list.
- `/health` answers GET only. Any other method, a trailing slash, and a Worker without `PUBLIC_ORIGIN` get the empty 404 (`noRouteResponse`).
- The ready line is printed by a script run after `wrangler deploy` succeeds (`&&`), so a failed deploy prints nothing.
- The runbook's production step 8 keeps calling `wrangler deploy` directly: `runbooks.test.ts` requires every wrangler call of the deploy runbook to go through the wrapper.
- `docs/self-host.md` is rendered into `apps/api/src/site/generated/self-host-html.ts`. Regenerating it is part of Lane S's green step, because `generated-site.test.ts` pins it.
- The walk has no README row and no committed screenshots. Screenshots are PR media only (ADR 0006). This drops the ADR 0047 cell question from the plan.
- Release's `NSAllowsLocalNetworking` is assumed to let `http://localhost:<port>` and `http://127.0.0.1:<port>` through App Transport Security. ADR 0056 claims it; nothing in the repository proves it. Step A4 and the walk prove it, and the failure mode table names the backout.

## Global Constraints

- An address is `https://` with a host, or `http://` only for `localhost`, `127.0.0.1` or `[::1]` (ADR 0056 § 3). A trailing slash is the only ending allowed. No path, query, fragment or credentials. The scheme's default port is dropped from the origin.
- The probe is `GET <url>/health` without following redirects; a redirect answers `notTodz`. It must answer `{"service":"todz","origin":"<PUBLIC_ORIGIN>"}` with `cache-control: no-store`. The origin must equal the origin typed.
- The switch order is exact (ADR 0056 § 5). Capture the old session. Erase the stored session, the cache with its outbox, the pending sign-in link and the sign-in method; each must throw and stop the switch before the owner service is rebuilt. Then the widget snapshot, in-memory state, phase `.signedOut(nil)`, the owner service and the change socket rebuilt through the factory, `serverURL`, and the preference write. No await sits between the erase and the preference write. The old server's sign-out goes last, detached, with the captured session, best effort.
- The ready line is exactly `todz server ready: <PUBLIC_ORIGIN>  →  paste it in todz › Settings › Server`, with two spaces on each side of `→`.
- Copy lives in `*Copy.swift` files. Enums over string literals. Magic numbers at the top of their file. No `??` that masks a missing value. No comments. No acronyms in identifiers. No `.js` extensions in imports. No `sleep`.
- Script names avoid pnpm built-ins (`server:deploy`, never `deploy`; learning 2026-10-17).
- The model's property is `serverURL` everywhere, typed `ServerAddress`; the defaults key is `serverURL`.

## Review Focus

1. An address with surrounding whitespace or an upper-case host, `" https://Todz.Example.com/ "`: accepted as the origin `https://todz.example.com`. Pinned by `ServerAddressTests` in step A1.
2. A probe that answers 200 with HTML, a site host's answer, or a redirect: `notTodz`, the switch does not start, the message is "No todz server answered at that address.". Pinned by `OwnerAPIHealthTests` in step A3 and by the walk.
3. A probe that answers todz with another origin, such as `127.0.0.1` typed for a Worker whose `PUBLIC_ORIGIN` is `http://localhost:8787`: refused with the origin named (`answersAs`). Pinned by `ServerProbeOutcomeTests` in step A3 and by the walk.
4. The old server unreachable when signing out: the switch goes on, and the sign-out failure is ignored. Pinned by `AppModelTests+Server` in step A5. An erase that throws keeps the old server and shows the error; pinned by the throwing-erase test in step A5.
5. The app quits mid-switch: the erase runs before the address is stored, so the next launch is on the old server, signed out with its data erased. Pinned by the order test in step A5.
