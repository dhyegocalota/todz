## Edge cases found during execution

- [ ] E1: the day close as the first popover opening of a launch (`open -g -j` twice, `open -g` once; the time two or three minutes ahead, three open Today tasks) — expected: the popover opens in the mode — FAIL, CRITICAL: SIGABRT 3 of 3, 7 to 14 s after the minute, nothing shown, `lastClosedDay` not written. Stack: the timer's `DayCloseScheduler.checkAgain(at:)` → `DayCloseCoordinator.check()` → `open()` → `MenuBarPanel.open()` (`MenuBarPanel.swift:20`) → `performClick`; while SwiftUI builds the popover, text layout runs `+[NSParagraphArbitrator initialize]` → `registerDefaults` → `UserDefaults.didChangeNotification` → `DayCloseScheduler.observe` (`DayCloseScheduler.swift:28`) → `check()` again, still due and not marked → `MenuBarPanel.open()` again (`window` nil, so not shown) → a second `performClick` → `WindowMenuBarExtraBehavior.toggleWindow` → `hide()` inside the update → `AG::precondition_failure`. With the popover opened once before in the launch the walk passed. This is the brief's known gap made real: `open()` counts a click as an open without knowing the window shows, and nothing stops a re-entrant check while one open is in flight.
