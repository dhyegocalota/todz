## Edge cases found during execution

1. Local `wrangler dev` enforces the limiter without the header: twelve `POST /owner/sessions` with no `CF-Connecting-IP` answered ten 201, then 429. The local runtime supplies the client address, so the briefing's hypothesis (no header, behaves as before in `wrangler dev`) is refuted: a developer or script signing in more than ten times a minute gets 429 locally; the explicit skip is reached only by unit tests. Outcome: observed (defect 5).
2. A spoofed `CF-Connecting-IP` is honoured locally (each value its own bucket), and `X-Forwarded-For` alone is ignored (twelve posts shared the no-header bucket and were all 429 once it was exhausted). Production relies on Cloudflare overwriting `CF-Connecting-IP`, which this run cannot prove. Outcome: held for X-Forwarded-For; spoof is local-only.
3. The per-email cap answers 429 `{"error":"too_many_links"}` (five 202, then 429 from other addresses with the same email), distinct from `too_many_requests`. Outcome: as designed.
4. Buckets are per route: with the session bucket of `203.0.113.9` exhausted, `POST /owner/sign-in-links` from it was not limited. Outcome: as designed.
5. Reads are unlimited: twelve `GET /owner/sign-in-method` from an exhausted address answered 200. Outcome: as designed.
6. Under `pnpm dev` (fake provider) a wrong identity token answers 201, not 401; runbook step 14's `401` holds only for the email provider, not run live. Outcome: unverified.
7. Runbook step 14 says a request a minute later answers `401` but has no command for it; step 12 expects `200 text/html` while curl's `%{content_type}` prints the charset too. Outcome: unverified, minor (defect 6).
8. The `jq` filters of runbook steps 3 and 10 could not be run: the sandbox hook blocks shell lines holding braces. Outcome: BLOCKED.
9. Tester disclosure: I ran `pkill -f workerd` once to stop my own `pnpm dev`; port 8787 and any Worker were free beforehand, but it could have hit another worktree's workerd. Nothing else was stopped.
