## Hypotheses

- Over the limit, `POST /owner/sign-in-links` and `POST /owner/sessions` answer 429 `{"error":"too_many_requests"}` with `Retry-After: 60` and the identical body; the two posts use separate buckets; another client address is unaffected.
- Without `CF-Connecting-IP`, or without the binding, both posts behave as before (`wrangler dev`, the other tests and the v1 scenario never meet the limiter).
- Nothing else on the owner API (a read, a task write, `GET /owner/sign-in-method`) calls the limiter.
- `pnpm dev`, `pnpm dev:email` and `pnpm dev:email:cloudflare` (from `apps/api`) still start a local Worker that sees `localhost:8787` as its host, so the console sender works and sign-in with the fake provider still passes, against the new local database name; state from earlier local runs stays behind under the old id.
- The Release build of the app, and only it, names `https://api.todz.app`; the app maps a 429 `too_many_requests` on either public post to `Too many attempts. Wait a minute and try again.` with no retry button.
- The runbook's commands match Wrangler 4.167.0's flags (`d1 export --remote --output`, `d1 migrations list|apply --remote`, `d1 time-travel info`, `email sending enable|dns get|list`, `rollback`, `delete`): the developer read each command's `--help`, never ran one.
- No script or runbook command line passes `--var` to `wrangler deploy`, and no `package.json` script has `--remote`.
