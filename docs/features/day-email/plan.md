# Plan: Day email

**Spec:** spec.md
**Tier:** 🔴
**Seam:** the owner row and `PATCH /owner` (two fields beside `agent_nudge`), the Worker's `scheduled` export (a dispatch module above the digest), a new `email` export, the routing module (a `ScheduledOwner` and a `ReplyOwner` beside `SessionOwner`), the generated mail module, and the Settings window over the app's one `AppModel`
**Assumptions (decided, owner can override):**
- `design.md`'s recommendations are the loop's calls; its copy is the copy.
- The app keeps its existing `updateOwner(session:timeZone:)` and `updateAgentNudge(session:isEnabled:)` and gains `updateDayEmail(session:isEnabled:)` and `updateDayEmailMinutes(session:minutes:)` on the same `PATCH /owner`, each sending one field (the server's partial contract).
- `Owner.dayEmail` and `Owner.dayEmailMinutes` are optional on the app's wire and decoded if present: `nil` means unknown and the row is disabled, so an older server still signs in.
- Every answer that carries `owner` (`GET /owner`, `PATCH /owner`, sign-in) reads both fields from the stored row, through the one `storeOwnerChanges … RETURNING` and `findOwner`; a new owner answers the column defaults (`false`, 420).
- The day mail's Today reads each project through the existing `listTasks` RPC (`state: open`, `dueWindows: [overdue, today]`, `limit: LIST_LIMIT_MAX`), using `totalMatched` for the count; no new project-store RPC.
- An owner with no workspace is never due (no Today and no Inbox), like one with zero or two `email` identities.
- The reply secret is 16 random bytes as lowercase hex from a new `generateReplySecret` beside `generateCredentialSecret`; its digest is `digestCredential`.
- Inbound tests call the Worker's `email` export with a fake `ForwardableEmailMessage` built from raw MIME fixtures in `apps/api/test/fixtures/day-email/` (`.eml` text, read through the existing raw-source import); Cloudflare's `Authentication-Results` line is part of each fixture, shaped like the header the spike (Step 9) captures.
- `postal-mime` is pinned exactly (4.2.1, ADR 0064) as a runtime dependency of `@todz/api`; `pnpm security:audit` stays clean.
- One rate limit namespace, 8610 (per owner), next after the admin's 8609; there is no global reply limiter (R6).
- Logs never carry an address, a subject, a header's text or a title; thrown messages neither.

## Sequencing

Server and App run in parallel, each in its own worktree branched from `feat/day-email`: the App codes against the JSON contract in spec § Interfaces with its fakes, never against the server's code. Inside Server, Steps 1–8 (the setting and the mail out) come before Steps 10–15 (the reply in), because both halves touch `env.ts`, `index.ts`, `wrangler.jsonc`, the constants and the shape test. The spike (Step 9) runs while Steps 1–8 are built and must answer before Step 10; if its header lacks `header.from` or `header.d`, ADR 0064 §3.7 is amended before Step 10's fixtures are written. The lead merges both lanes into `feat/day-email` by merge, then runs Docs. Production steps (Step 21 onward) wait for the merge and the deploy.
