# Plan: Day email

**Spec:** spec.md
**Tier:** 🔴
**Seam:** the owner row and `PATCH /owner` (two fields beside `agent_nudge`), the Worker's `scheduled` export (a dispatch module above the digest), a new `email` export, the routing module (a `ReplyOwner` beside `SessionOwner`), the generated mail module, and the Settings window over the app's one `AppModel`
**Assumptions (decided, owner can override):**
- `design.md`'s recommendations are the loop's calls; its copy is the copy.
- The app keeps its existing `updateOwner(session:timeZone:)` and `updateAgentNudge(session:isEnabled:)` and gains `updateDayEmail(session:isEnabled:)` and `updateDayEmailMinutes(session:minutes:)` on the same `PATCH /owner`, each sending one field (the server's partial contract).
- `Owner.dayEmail` and `Owner.dayEmailMinutes` are optional on the app's wire and decoded if present: `nil` means unknown and the row is disabled, so an older server still signs in.
- Every answer that carries `owner` (`GET /owner`, `PATCH /owner`, sign-in) reads both fields from the stored row, through the one `storeOwnerChanges … RETURNING` and `findOwner`; a new owner answers the column defaults (`false`, 420).
- The day mail's Today reads each project through the existing `listTasks` RPC (`state: open`, `dueWindows: [overdue, today]`, `limit: LIST_LIMIT_MAX`), using `totalMatched` for the count; no new project-store RPC.
- An owner with no workspace is never due (no Today and no Inbox), like one with no `email` identity.
- The reply secret is 16 random bytes as lowercase hex from a new `generateReplySecret` beside `generateCredentialSecret`; its digest is `digestCredential`.
- Inbound tests call the Worker's `email` export with a fake `ForwardableEmailMessage` built from raw MIME fixtures in `apps/api/test/fixtures/day-email/` (`.eml` text, read through the existing raw-source import); the first `Authentication-Results` line is part of each fixture.
- `postal-mime` is pinned exactly (4.2.1, ADR 0064) as a runtime dependency of `@todz/api`; `pnpm security:audit` stays clean.
- Rate limit namespaces 8610 (per owner) and 8611 (global), next after the admin's 8609.

## Sequencing

Server and App run in parallel, each in its own worktree branched from `feat/day-email`: the App codes against the JSON contract in spec § Interfaces with its fakes, never against the server's code. Inside Server, Steps 1–8 (the setting and the mail out) come before Steps 9–12 (the reply in), because both halves touch `env.ts`, `index.ts`, `wrangler.jsonc`, the constants and the shape test. The lead merges both lanes into `feat/day-email` by merge, then runs Docs. Production steps (Step 18 onward) wait for the merge and the deploy.

`feat/landing-seo` also changes `apps/api/src/index.ts`, `scripts/emails/email-style.ts` and the generated mail module; `feat/morning-glance` is likely to change `SettingsView.swift` and `SettingsCopy.swift`. Whoever merges second merges `main` at a step boundary, reruns `pnpm emails:generate` for the generated module (never hand-merges it) and keeps both Settings rows.

## Failure modes

| Step | What breaks | How I notice (the concrete signal) | How I back out |
|------|-------------|------------------------------------|----------------|
| 2 | Migration 0008 fails on production D1 | `wrangler d1 migrations apply` exits non-zero | Additive only; fix the SQL and re-apply |
| 2 | Sign-in answers the defaults for an owner who set them | The row turns off after every sign-in | Read the stored row (Step 1 pins it) |
| 4 | Another mail loses its `hello@` reply-to | A reply to the welcome goes nowhere | `filledEmailOf`'s default; Step 3 pins each builder |
| 6 | The due rule fires twice on a DST day or never in a quarter-hour zone | Two rows impossible (primary key) but two mails if the claim is skipped; no row for Kolkata | The claim is the only path to a send; Step 5's zone cases |
| 6 | A tick runs past its limits with many owners | The invocation fails with a subrequest or CPU error | The 50-per-tick cap; lower it in `libs/types` |
| 6 | The digest stops after the dispatch move | No digest at 11:00 UTC; `scheduled.test.ts` red | The digest tests run through the new dispatch |
| 7 | The `*/15` cron is not deployed | No `day_emails` rows after a due time | Shape test; redeploy |
| 11 | A forged reply adds a task | A task the owner did not write | Delete the routing rule at once (one call); fix and redeploy |
| 11 | Legitimate replies are refused (Gmail's header shape differs from the docs) | No task after the owner's reply; the log says `unauthenticated` | The `unauthenticated` log line carries only `isCloudflareFirst` and the `dmarc` verdict word (never `smtp.mailfrom` or `header.from`); read it in Workers Logs, add the real shape as a fixture, adjust the parser red-first; never loosen to "any header" |
| 11 | `postal-mime` fails in workerd | The handler rejects on every message | Pin and test in workerd (Step 10 runs there) |
| 14 | An owner answer without the fields fails to decode | Sign-in fails for every owner | Both fields optional, decoded if present |
| 18 | The token cannot write Email Routing | 403 or an authentication error from the wrapper | Owner step; the mail out works without it |

**Steps with no backout:** none. Migration 0008 only adds; the routing rule and subaddressing are removed by one call each; mail already sent cannot be recalled, which is the feature.
