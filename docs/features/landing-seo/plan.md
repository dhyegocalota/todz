## Sequencing

1. G0 lands first on `feat/landing-seo` (step 1): the two constant modules both lanes import.
2. Lanes H and I then run in parallel, each in its own worktree on a branch from `feat/landing-seo` (`feat/landing-seo-h`, `feat/landing-seo-i`), merged back by the lead.
3. Lane H's steps 2–15 need nothing from Lane I: the head points at the icon paths in `site-icons.ts`, and its unit tests check the tags, not the files. Lane H's e2e asset rows (step 14) go green only once Lane I is merged into H; until then they stay red and the briefing says so.
4. Step 16 (performance) runs after the lead merges Lane I (step 21's derivatives) into H.
5. Merge order with the open siblings (Failure modes, rows M1–M4): rebase never; merge `main` into this branch after each sibling lands, and rerun the affected tests.

## Failure modes

| Step | What breaks | How I notice (the concrete signal) | How I back out |
|------|-------------|------------------------------------|----------------|
| 3 | A tag's value carries unescaped copy | `site-head.test.ts` sees `&` or `"` raw; the HTML validator in the e2e fails | Every attribute value through `escapedHtml` |
| 5 | The JSON-LD text hashed differs from the text written (a newline, escaping) | A `securitypolicyviolation` in the e2e; `site-pages.test.ts` hash red | Hash the exact string the shell writes, built once at module load |
| 5 | `</script>` inside a JSON string closes the block | Parse fails in `site-json-ld.test.ts` | Serialize with `<` escaped as `<` |
| 5 | `no-transform` stops a Cloudflare feature the site relies on | Production compression or caching changes; nothing else uses transforms today | Revert the one constant |
| 9 | The Worker never sees `/robots.txt` because an asset or a Cloudflare rule answers first | Production `robots.txt` is Cloudflare's preamble only | No asset of that name exists; the deploy step reads the body; the owner turns off the zone's managed `robots.txt` if it replaces the Worker's |
| 9 | Cloudflare prepends its content-signals preamble | The production body starts with `# As a condition of accessing` | Accepted (comments); Lighthouse `robots-txt` on production is the check |
| 11 | The `/mcp/server-card` route shadows or is shadowed by `/mcp` | `mcp-server-card.test.ts` or `mcp-endpoint.test.ts` red | Exact path keys in `ROUTE_OF_PATH`; revert the line |
| 13 | `registerTool` throws synchronously in a real browser and stops the page script | Console error in the e2e or the walk | Each registration in its own `try` and `catch` of the returned promise; the script is separate from `PAGE_SCRIPT` |
| 13 | A browser exposes both names and the tools register twice | Duplicate-name rejection logged | `document` first; `navigator` only when `document` has none |
| 13 | `join_waitlist` submits with a blank token | `POST /join` without `cf-turnstile-response` in the e2e | It calls `requestSubmit()`, which runs the page's own handler; never `submit()` |
| 15 | The ratio fix moves the hero layout | Desktop or mobile screenshot differs from the before shot | Revert the CSS; fix the source dimensions instead |
| 16 | Performance stays under 95 | The median of three runs | Each fix is its own commit, reverted alone; escalate with the trace if all three are done |
| 20 | Chromium renders differ between runs or machines | The double render differs; `site:assets:check` red on another machine | Check size and format only (step 20) |
| 20 | Rasterized icons lose the drop shadow or gradient | Visual compare with `todz-loop/brand/todz-icon-1024.png` | Render the large sizes at 2x and downscale |
| 24 | Production differs from `wrangler dev` (headers, managed `robots.txt`, bot rules) | The new runbook step's curls; `GPTBot` answered 403 | Roll back per the runbook; a 403 to AI crawlers is a zone setting the owner changes |
| M1 | `security-fixes` lands first: `withSecurityHeaders` adds HSTS, `nosniff`, `Referrer-Policy` and a default CSP to answers that lack them; it edits `landing-page.ts` (`data-error-callback` and `PAGE_SCRIPT`), `site-pages.test.ts`, `landing.spec.ts`, `_headers` and runbook steps 13–14 | Merge conflicts in `landing-page.ts`, `site-pages.test.ts`, `deploy-the-api.md`; the discovery routes' header tests see extra headers | Merge `main`, keep both edits; discovery routes set their own `Content-Type` and `Cache-Control` and the wrap only fills absent ones; the page script's new hash is taken by the list in step 5 |
| M2 | `docs-mintlify` lands first: it changes `generated-site.ts`, `self-host-html.ts` and the self-host source path, and adds `/health` to `index.ts` | Conflict in `index.ts`'s import list; `/self-host` content changes | Merge `main`; this lane never edits those files; `DOCS_URL` pages exist only after it ships, so `open_docs` targets are checked again then |
| M3 | `server-url` lands first: `index.ts` (`/health`), `turnstile-page.ts`, `wrangler.jsonc` `run_worker_first` | Conflict in `index.ts` | Merge `main`, keep both lines |
