# Plan: Docs on Mintlify

**Spec:** spec.md
**Tier:** 🔴
**Seam:** a new workspace package `apps/docs` that Mintlify reads; the guide's file, which the landing's generator reads through `guideMarkdown`; a `docs` gate in `scripts/verify.sh`, green before any merge that publishes; a runbook recording the owner's Mintlify setup (done 2026-11-25) and the loop's checks before and after a merge
**Assumptions (decided, owner can override):**
- `mint@4.3.91` and the client `0.0.4077` come from run 17's spike (ADR 0059 § Evidence). D2 opens with a check of the pin inside `apps/docs` under pnpm 8.15.9 (R4). If a page shows the `__dirname` console error with that client, the step stops, the developer tries the newest client that renders cleanly, and the pin, the ADR's evidence and this line change in the same commit.
- `mint dev` takes `--port <n> --no-open`; the walk's config runs `pnpm run dev --port <n> --no-open`, and pnpm 8.15.9 passes the flags through to the script, so the version pins live only in `apps/docs/package.json`. D2's check confirms the pass-through (R4).
- Mintlify's anchors for the guide's headings are the lower-cased words joined by hyphens (`#7-build-the-macos-app-and-point-it-at-your-server`, `#updating`); `mint broken-links` checks them (spike: `/self-host#updating` resolves).
- The guide keeps no link into the repository (R8): its four repository links become the plain text the landing already shows for them, so the landing's generated page changes only in its header line and the two key-screen labels.
- `repository-shape` does not import workspace packages: its tests read the source files they pin (`mcp-copy.ts`, `mcp-tool-arguments.ts`, `AgentCommand.swift`, the Swift copy files, `landing-copy.ts`, `site-style.ts`, `libs/types/src/constants.ts`, `wrangler.jsonc`) as text, through the shared helpers of L0 where two tests need the same reading.
- `gate_docs` calls `pnpm --filter @todz/docs --fail-if-no-match …` (R5), so Lane G alone cannot pass `pnpm verify` for an `apps/docs` path: the package does not exist on its branch. Lane G proves its part with `pnpm test:verify` and the suites it names; the lead's L2 on the merged branch is the first real run of the gate.

## Global Constraints

- English only. Page titles live in front matter; no page has its own `# ` heading.
- The pins are the single source: no page states a command, URL, label, tool description or colour that a shape test does not compare with the code, except prose.
- No page links into the repository while it is private; the guide names repository paths as code spans.
- `.mdx` files are not formatted by Prettier (`*.mdx` joins `*.md` in `.prettierignore`); `docs.json`, `.ts` and `.json` files are.
- The Playwright config names every timeout as a `*_MS` constant (`test-timeouts.test.ts`), takes its port only from `docsPortOf`, uses the system Chrome when the bundled Chromium is missing (as `apps/api/playwright.config.ts` does), and ignores `_*.spec.ts`.
- The noise allow-list has one entry per pattern, each with a `reason`, and matches nothing on a page's own requests.
- No `sleep`, no `??` that masks a missing value, no comments other than `// NB ADR 0059:` pointers, enums over string literals, constants over literals, named parameters past one.
- Lane branches take each other by merge, never by rebase.

## Review Focus

1. The guide's one source: after the move, no other file holds the guide's text but the generated page, and `site:check` fails when they drift. Pinned by `generated-site.test.ts` (G1, G3) and `self-host.test.ts` (G1).
2. A merge publishes: every merge to `main` that touches `apps/docs` goes live on `docs.todz.app`, so `broken-links` and `validate` are in the `docs` gate that `verify` runs for any `apps/docs` path before the merge, the gate fails when the package is missing instead of passing on no match, and the runbook's check after the merge tells todz's pages from the starter kit. Pinned by `verify.test.sh` (G6) and `runbooks.test.ts` (G4).
3. The client pin: the walk fails on any console error, failed request or answer of 400 or more, so a client that throws is caught. Pinned by D2's check, the walk fixture (D3) and the tester's mutation.
4. The commands on Connect an agent are the app's: a change to `AgentCommand.swift`'s templates or constants, or to `PUBLIC_ORIGIN`, fails `docs-pages.test.ts` (D1).
