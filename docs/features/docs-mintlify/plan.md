# Plan: Docs on Mintlify

**Spec:** spec.md
**Tier:** 🔴
**Seam:** a new workspace package `apps/docs` that Mintlify reads; the guide's file, which the landing's generator reads through `guideMarkdown`; a `docs` gate in `scripts/verify.sh`, green before any merge that publishes; a runbook recording the owner's Mintlify setup (done 2026-11-25) and the loop's checks before and after a merge
**Assumptions (decided, owner can override):**
- `mint@4.3.91` and the client `0.0.4077` come from run 17's spike (ADR 0059 § Evidence). If the walk shows the `__dirname` console error with that client, the step stops, the developer tries the newest client that renders cleanly, and the pin, the ADR's evidence and this line change in the same commit.
- `mint dev` takes `--port <n> --no-open`; the walk's config passes them after `pnpm run dev`, so the version pins live only in `apps/docs/package.json`.
- Mintlify's anchors for the guide's headings are the lower-cased words joined by hyphens (`#7-build-the-macos-app-and-point-it-at-your-server`, `#updating`); `mint broken-links` checks them (spike: `/self-host#updating` resolves).
- The landing's generator keeps rendering the guide's first heading as `<h1 id="self-host-todz">Self-host todz</h1>`; only the four repository links and the two key-screen labels change in the generated page.
- `repository-shape` does not import workspace packages: its tests read the source files they pin (`mcp-copy.ts`, `mcp-tool-arguments.ts`, `AgentCommand.swift`, the Swift copy files, `site-style.ts`, `libs/types/src/constants.ts`, `wrangler.jsonc`) as text.
- `pnpm --filter @todz/docs …` before Lane D lands matches no project; Lane G's own `pnpm verify` runs are not the proof of the `docs` gate. The lead's `pnpm verify all` on the merged branch is.

## Global Constraints

- English only. Page titles live in front matter; no page has its own `# ` heading.
- The pins are the single source: no page states a command, URL, label, tool description or colour that a shape test does not compare with the code, except prose.
- `.mdx` files are not formatted by Prettier (`*.mdx` joins `*.md` in `.prettierignore`); `docs.json`, `.ts` and `.json` files are.
- The Playwright config names every timeout as a `*_MS` constant (`test-timeouts.test.ts`), uses the system Chrome when the bundled Chromium is missing (as `apps/api/playwright.config.ts` does), and ignores `_*.spec.ts`.
- The noise allow-list has one entry per pattern, each with a `reason`, and matches nothing on a page's own requests.
- No `sleep`, no `??` that masks a missing value, no comments other than `// NB ADR 0059:` pointers, enums over string literals, constants over literals, named parameters past one.
- Lane branches take each other by merge, never by rebase.

## Review Focus

1. The guide's one source: after the move, no other file holds the guide's text but the generated page, and `site:check` fails when they drift. Pinned by `generated-site.test.ts` (G3) and `self-host.test.ts` (G1).
2. A merge publishes: every merge to `main` that touches `apps/docs` goes live on `docs.todz.app`, so `broken-links` and `validate` are in the `docs` gate that `verify` runs for any `apps/docs` path before the merge, and the runbook's check after the merge tells todz's pages from the starter kit. Pinned by `verify.test.sh` (G6) and `runbooks.test.ts` (G4).
3. The client pin: the walk fails on any console error, so a client that throws is caught. Pinned by the walk fixture (D3) and the tester's mutation.
4. The commands on Connect an agent are the app's: a change to `serverName`, `keyVariable` or `serverPath` in `AgentCommand.swift`, or to `PUBLIC_ORIGIN`, fails `docs-pages.test.ts` (D1).

## Failure modes

| Step | What breaks | How I notice (the concrete signal) | How I back out |
|------|-------------|------------------------------------|----------------|
| G2 | the rename loses the file's history | `git log --follow apps/docs/self-host.mdx` stops at the move | redo the move as a commit holding only the rename and its path followers |
| G2 | a follower still reads `docs/self-host.md` | `site-pages.test.ts` fails to import, `landing.spec.ts` throws `ENOENT`, or `site:check` cannot read the guide | `git grep -n "docs/self-host.md" -- apps scripts tools README.md` names the follower; fix the path |
| G3 | the generated page's heading changes | `landing.spec.ts`'s `level: 1` check or the e2e heading list fails; the generated diff touches more than the header, four links and two labels | fix `guideMarkdown`; regenerate |
| G3 | the guide holds text MDX cannot parse (a bare `<` or `{` outside code) | `mint validate` fails at D2 or L2, naming the line | put the text in a code span; regenerate |
| G3 | `**Connect an Agent**` differs from the app | test (d) fails | read `KeyScreenCopy.title`; the app is the source |
| G5 | the check after the merge cannot tell todz's pages from the starter kit | step 3 passes on a page that is not ours | the strings it asks for (`Self-host todz`, the credit line) exist only in todz's pages; `runbooks.test.ts` pins the URLs, the tester reads the starter kit's answer once before the merge |
| G5 | Mintlify's HTML holds the text only after client rendering | `curl` of a page built from this feature misses `Self-host todz` | a docs PR changes step 3 to ask for the page's `<title>`; the walk of step 4 stays the proof |
| G7 | the `docs` gate runs on paths that do not touch the docs | `verify --plan` for an `apps/api` file lists `docs` | the row order in `verify-gates.tsv`; `verify.test.sh` is the pin |
| G7 | the self-host row loses the `@todz/api` unit suite | `verify --plan` for the guide lists no package | restore `unit docs	apps/api` on the row |
| D1 | `pnpm install` changes other packages' resolutions | `pnpm-lock.yaml`'s diff touches importers other than `apps/docs` | restore `pnpm-lock.yaml` from the branch's base and run `pnpm install --filter @todz/docs`; never bump another package |
| D2 | the pinned client throws in the browser (`__dirname is not defined`) | the walk fixture fails on the console error | the assumption's procedure: the newest clean client, the pin and the ADR's evidence in one commit |
| D2 | `broken-links` misses an anchor | the Playwright walk lands on the page's top instead of the heading | a walk check for that anchor; note it in the briefing |
| D3 | the walk catches noise the allow-list does not name | a walk fails on a request to a `mint dev` internal path | add one entry with its reason; never widen an entry to a page's own requests |
| D3 | `mint dev` fails to start on the free port | Playwright's `webServer` times out | the config's server timeout and port helper; run `pnpm --filter @todz/docs dev --port <n> --no-open` by hand to read the error |
| D5 | the layout line drifts from the package | `delivery-docs.test.ts` or the reviewer | edit the line |

**Steps with no backout:** none before the merge: every step is a commit on the lane branch, and nothing changes DNS or deploys. The merge itself publishes `docs.todz.app` (replacing the starter kit); its backout is a revert, under the runbook's rollback.
