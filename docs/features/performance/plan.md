# Plan: Performance

**Spec:** spec.md
**Tier:** 🟡
**Seam:** a new workspace package `tools/perf` that drives the Worker from outside; the API's request entry (`apps/api/src/index.ts`) for `Server-Timing`; the `TaskStore` port and the project store's schema for the order and history reads; the app's model (`AppModel`, `TaskBoard`, the cache writes) and a probe in the app target
**Assumptions (decided, owner can override):**
- Everything ADR 0061 decides, and the loop's calls in the spec's open questions.
- Node 24's global `WebSocket` (undici) accepts a `headers` init, so the harness can send `Authorization` on the socket. Step 11's red test proves it against `wrangler dev`; if it cannot, the harness pins `undici` at the version Node 24.x bundles as a devDependency of `@todz/perf` and names it in the PR body (Failure modes, row L11).
- The Debug app signs in to `wrangler dev` through the fake provider with the identity `pnpm perf seed` prints, so the app's 5,000-task walk needs no mail.
- `security-fixes` is on `main` (PR #43): `withSecurityHeaders` wraps every answer in `index.ts`, and `Server-Timing` is set inside that wrap.
- `landing-seo` is building on `feat/landing-seo` and edits `apps/api/src/index.ts` (one path-table line), `apps/api/src/mcp-server.ts` (exports the version), `apps/api/src/site/**` and `docs/runbooks/deploy-the-api.md`. This plan never edits the last two while `landing-seo` is unmerged, and merges `main` before touching the first two again once it lands.
- The free Workers plan caps CPU at 10 ms per request; a production 5xx with outcome `exceededCpu` in `wrangler tail` is a server finding for Lane S, never a harness bug.

## Failure modes

| Step | What breaks | How I notice (the concrete signal) | How I back out |
|------|-------------|------------------------------------|----------------|
| 2 | `tools/perf` is not in the gate map and falls to `all` | `pnpm verify --plan` on a `tools/perf` change lists every gate; the new `verify.test.sh` case fails | Fix the row's order in `verify-gates.tsv` |
| 2 | A devDependency resolves to a version not in the lockfile | `pnpm install --frozen-lockfile` fails, or `git diff pnpm-lock.yaml` shows a new package | Pin to the version the lockfile already holds; revert the lockfile |
| 11 (L11) | Node's `WebSocket` drops the `Authorization` header | The live test answers 401 on the upgrade | Pin `undici` at Node 24's bundled version as a devDependency of `@todz/perf`; named in the PR |
| 11 | The SDK client's requests differ from what the harness assumes (for example a `notifications/initialized` round trip) | The legacy-era test counts an extra request | Count it as part of the handshake, never in `tools/call` latency |
| 13 | The key leaks into output | The leak test finds the key in the report, an error or the sends file | Revert the step; the owner rotates the key (revoke and issue) |
| 19, 27, 34 | Local numbers swing between runs on a loaded Mac | Two runs of the same commit differ by more than 30% at p95 | Run three times, record the median run, and say so in the row |
| 21 | `Server-Timing` breaks an answer kind (the 101 upgrade, a streamed MCP answer) | `security-headers.test.ts` or an MCP test goes red | Revert step 21; attribution falls back to local profiles |
| 24, 26 | The version-3 migration fails on an existing project store | `project-schema.test.ts` red; in production, MCP calls on old projects answer 500 | Revert the code: a version-2 build runs on a version-3 store unchanged, because the change is indexes only |
| 24 | The new order reads change a placement | An `update-task` or `add-tasks` test goes red | Revert to `listAllTasks` for the failing placement and record it |
| 28 (C4) | The joined statement lets a session reach another owner's project | An `owner-isolation` test goes red | Revert the C4 commits |
| 33 | The probe runs without its argument | A log line or a display link appears in a plain launch (`log show` after `open -g` without arguments shows `perf` lines) | Revert step 33's app files; the TodzKit parts are inert |
| 35 | The 8 ms ceiling is noise in the Debug build on a loaded Mac | `macos` gate red on a commit that does not touch TodzKit | Record the Debug and the `swift test -c release` medians in a learning; the lead amends ADR 0061 § 8 with a Debug ceiling, never silently |
| 37 | The background writer loses a write at quit | A relaunch shows a task's older copy | Flush the writer on `applicationWillTerminate`; if that fails, revert step 37 |
