# Plan: Performance

**Spec:** spec.md
**Tier:** 🟡
**Seam:** a new workspace package `tools/perf` that drives the Worker from outside; the API's request entry (`apps/api/src/index.ts`) for `Server-Timing`; the `TaskStore` port and the project store's schema for the order and history reads; the app's model (`AppModel`, `TaskBoard`, the cache writes) and a probe in the app target
**Assumptions (decided, owner can override):**
- Everything ADR 0061 decides, and the loop's calls in the spec's open questions.
- Node 24's global `WebSocket` (undici) takes `{ headers }` in its init, so the harness can send `Authorization` on the socket. Step 11 proves it in a unit test against a local `node:http` server that accepts the upgrade and records the headers (R10). If it cannot, the fallback is `undici@7.30.2`, already in the lockfile, as an exact-pinned devDependency of `@todz/perf`, named in the PR body (Failure modes, row L11).
- The Debug app signs in to `wrangler dev` through the fake provider with the identity `pnpm perf seed` prints, so the app's 5,000-task walk needs no mail.
- `security-fixes` is on `main` (PR #43): `withSecurityHeaders` wraps every answer in `index.ts`, and `Server-Timing` is set inside that wrap.
- Siblings overlap wider than the product files (R16). `landing-seo` edits `apps/api/src/index.ts` (one path-table line), `apps/api/src/mcp-server.ts` (exports the version), `apps/api/src/site/**`, `docs/runbooks/deploy-the-api.md`, and, as every feature does, `docs/features/README.md` and `docs/adr/README.md`; `landing-seo` and `docs-mintlify` may also touch `docs/runbooks/README.md`, `tools/repository-shape/src/runbooks.test.ts`, `scripts/verify-gates.tsv`, `scripts/verify.test.sh`, `package.json` and `pnpm-lock.yaml`. This plan never edits `apps/api/src/site/**` or `deploy-the-api.md` while `landing-seo` is unmerged; for every shared file, the lane that owns it here merges `main` at its next step boundary whenever a sibling lands, and the lead re-checks that 0061 is still the next free ADR number before the merge to `main`.
- The free Workers plan caps CPU at 10 ms per request; a production 5xx with outcome `exceededCpu` in `wrangler tail` is a server finding for Lane S, never a harness bug.
- The production run's tasks carry a run identifier in their title and idempotency key; the harness completes only tasks that carry its own identifier (R2).
