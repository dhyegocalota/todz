## Edge cases found during execution

Found by the tester at c9b2168, scripted against a local wrangler dev (2026-11-25). Defects need a regression test from the developer.

- **DEFECT (minor): a link pasted into a tab that already shows `/admin/sign-in` does nothing and keeps the token in the address bar.** Input: open a refused link (page shows "This link can't be used.", address bar `/admin/sign-in`), then paste a valid link `/admin/sign-in#token=<43 chars>` into the same tab. Observed: the navigation is hash-only, the script does not run again, the heading stays "This link can't be used." and the address bar keeps `#token=<token>` (token stays in history, no `replaceState`). Expected: the page reacts to the new fragment, or the token never stays visible. In a new tab the same link lands on `/admin`. A page reload of that tab would post the token; not tried.
- **Deviation from design.md section 1 (known in the briefing, confirmed):** the "Self-host guide" link stays in the header of every admin page, including the sign-in cards, and Sign out sits in the panel's action row next to Download CSV instead of the header. Shots: `sign-in-1280-light.png`, `panel-top-1280-light.png`.
- Console and network: the only error in the whole walk is `401` on `POST /admin/sessions` for each deliberately refused link (browser logs it as a console error); a `net::ERR_ABORTED` is reported for the same request when the context closes. Landing images `/landing/*.png` reported `ERR_ABORTED` when the seeding step left `/` right after a join (not the admin). No other console message, no failed request, and the only origins called were the site, the Turnstile script and the fake mail page.
- Two browser tabs asking for links in one browser: the second request replaces the challenge cookie. The first mailed link is then refused in that browser ("This link can't be used."), the second lands on `/admin`. Expected by the design, but the first mail dies silently.
- A token in the query string (`/admin/sign-in?token=...`): the page is the same fixed document, the token is not echoed, nothing is spent; `POST /admin/sessions?token=...` with body `{}` answers 401.
- Link page with no fragment and with `#token=garbage`: both show "This link can't be used."; the garbage fragment stays in the address bar (no request is made, nothing to protect).
- A challenge value copied into the session cookie, or two copies of the real session cookie: the sign-in card, no panel.
- Cookie from the API host, `api.todz.app` and `www.todz.app` host checks: NOT RUNNABLE locally; wrangler dev rewrites the `Host` header, so a spoofed host answers the site page. Only the unit tests (`site-dispatch.test.ts` through `worker.fetch`) prove them; the production smoke walk must check `https://api.todz.app/admin` (404) and `https://www.todz.app/admin` (301).
- Sign out then the back button: the browser lands on `/admin` and shows the sign-in card (the panel is `no-store`, not served from cache); `/admin/export.csv` after sign-out redirects to `/admin`; a copy of the old cookie in a fresh context shows the sign-in card.
- Limits on a local host: the three limiters and siteverify are bypassed by design (`isLocalSiteHost`), so only the per-address cap of five links per fifteen minutes was exercised live; every limit refusal is proven by unit tests only.
- Timing of the admin versus another address: 20 alternating requests, mean 3 ms each on the local host (the first call 23 ms and 6 ms are cold start). Not a real measurement of the Cloudflare edge.
- Long addresses: a 257-character address wraps at 375 with no horizontal scroll (`panel-long-address-375-light.png`); every panel at 1280 and 375, light and dark, has `scrollWidth` equal to the viewport.
