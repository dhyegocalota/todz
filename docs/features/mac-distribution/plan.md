# Plan: Mac distribution

**Spec:** spec.md
**Tier:** 🔴
**Seam:** the Worker's static assets (the staged directory `wrangler deploy --assets` takes, its `_headers` and `_redirects`), the hero of `landing-page.ts`, `apps/macos/project.yml` and the app's commands, and two new scripts beside `scripts/todz-cloudflare.sh`.
**Assumptions (decided, owner can override):**
- Sparkle `2.10.1`, pinned by its commit `ab7d71291238df6e0492143b120c9b696a35f603` (the tag's object on 2026-11-25). It supports signed feeds (`SURequireSignedFeed`, `SUVerifyUpdateBeforeExtraction`, `sign_update` on an XML feed) and gentle scheduled-update reminders, read from its sources at that tag.
- The first release is `0.2.0` (the project's `MARKETING_VERSION` is `0.1.0`, which was never published).
- The release key's principal is `release@todz.app`, its namespace `todz-release`.
- `~/.todz-release/` (mode `700`, outside git) holds `builds/<version>/` (every build, dry runs included: the DMG, `.sha256`, `.sig`, the signed `appcast.xml`, `commit`), `site/download/<version>/` (only versions a real release copied), `site/released` (one version per line, appended only after the production checks pass) and `packages/`.
- A deploy serves the latest two versions listed in `released`; "latest" is one line of the staged `_redirects`.
- Every Worker deploy goes through `scripts/deploy-worker.sh`, which stages and deploys with `--message <HEAD sha>`; the token is the existing `todz-cloudflare` Keychain item behind `scripts/todz-cloudflare.sh` (Workers Scripts Edit covers assets); no R2 permission is asked for.
- `waitlist-inline` and `mac-install-docs` merge before G1 starts; G1 merges `main` first.
