# Plan: Mac distribution

**Spec:** spec.md
**Tier:** 🔴
**Seam:** the Worker's static assets (the staged directory `wrangler deploy --assets` takes, its `_headers` and `_redirects`), the hero of `landing-page.ts`, `apps/macos/project.yml` and the app's commands, and two new scripts beside `scripts/todz-cloudflare.sh`.
**Assumptions (decided, owner can override):**
- Sparkle `2.10.1` is the pinned version (latest on 2026-11-25, published 2026-10-25).
- The first release is `0.2.0` (the project's `MARKETING_VERSION` is `0.1.0`, which was never published).
- The release key's principal is `release@todz.app`, its namespace `todz-release`.
- The release folder is `~/.todz-release/site/`, outside git, mode `700`; every version built stays there, and a deploy serves the latest two.
- "Latest" is one line of the staged `_redirects`, written from the release folder's newest version; the deployed appcast's `sparkle:version` is production's build number.
- The deploy token is the existing `todz-cloudflare` Keychain item behind `scripts/todz-cloudflare.sh` (Workers Scripts Edit covers assets); no R2 permission is asked for.
- `waitlist-inline` and `mac-install-docs` merge before G1 starts; G1 merges `main` first.

## Failure modes

| Step | What breaks | How I notice (the concrete signal) | How I back out |
|------|-------------|------------------------------------|----------------|
| D2 | The skill skips a runbook step or deploys a dirty tree | `deploy-skill.test.ts` red, or a run without its run-log row | revert the skill commit; deploys fall back to the runbook by hand |
| D2 | A release check fails after the deploy | the skill stops at check (4) and names it | nothing: the release command already rolled the Worker back to the deployment before |
| 15 | A deploy without the release folder removes the downloads | `stage-site-assets.sh` exits "would remove the published download"; or, if bypassed, `/download/latest` answers `404` after a deploy | deploy from the Mac that holds `~/.todz-release`, or `wrangler rollback` |
| 15 | `_headers` cannot set `Content-Type` on an asset | step 4's E2E: `.sha256` served as `application/octet-stream` | accept the inferred type for the two text files and record it; `curl` and `shasum` read them alike |
| 14 | A DMG over 25 MiB | the staging refuses and names the file | ADR 0072's R2 fallback, through a superseding ADR |
| 5 | The hero collides with `waitlist-inline` | conflict markers, or `site-pages.test.ts` red after the merge from `main` | merge `main` before step 3, as sequenced |
| 5 | `main` deployed before the first release | the button answers `404` on `todz.app` for the minutes between the deploy and the release (runbook steps 6 and 7, the skill's order) | finish the release |
| 8 | Sparkle cannot be fetched by the macOS gate | `xcodebuild` "Could not resolve package dependencies" | retry with network; the pin stays |
| 8 | The hardened runtime breaks the app or the sign-in web view | the Release app crashes at launch or the check page stays blank | `ENABLE_HARDENED_RUNTIME: NO`, an ADR 0072 amendment |
| 12 | The sandboxed installer cannot start | Sparkle: "An error occurred while launching the installer" | check the mach-lookup names against the bundle identifier; ship without Sparkle and re-release |
| 17 | A release stops halfway | the script exits non-zero after the build or the deploy | re-run: the release folder's files are reused, a deployed version with the same sum is "already published" |
| 17 | An appcast signed with the wrong key | the runbook's update check: Sparkle "The update is improperly signed" | `wrangler rollback` to the deployment before |
| Z | Gatekeeper kills the app on another Mac | the owner's check: "Todz is damaged" or killed at launch, or the App Group prompt | ADR 0072 decision 1's fallback through a superseding ADR; nothing published yet |

**Steps with no backout:** the first `pnpm release:mac` that deploys (runbook step 7: a downloaded DMG cannot be recalled; a rollback stops further downloads), and shipping `SUPublicEDKey` in a release (step 10: changing it later needs every installed copy downloaded again).
