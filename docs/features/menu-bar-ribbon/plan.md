# Plan: Menu bar ribbon

**Spec:** spec.md
**Tier:** 🟡
**Seam:** the `MenuBarExtra` label (`apps/macos/Todz/MenuBar/MenuBarLabel.swift`), which already draws the glyph and the count as one template image (ADR 0065); the proactive gate (`ProactiveGate`, `ProactiveSurface.ribbon`); the pull's `record(_:)` in `AppModel+Pull.swift`; the Settings form.
**Assumptions (decided, owner can override):**
- Off by default, cadence every hour (ADR 0071 §1).
- The first open task of `taskViews.today.open` is "next", as the popover lists it.
- Frames are crops of one strip rendered once per ribbon; the label takes a new image per frame. Step 0 proves it or the fallback of ADR 0071 §8 applies.
- A completion that arrives through a pull counts as an agent change, whoever made it (a task record has no completer).
- Red stubs `fatalError("<name> is not implemented")` live only in G1's own red commits; G2 never builds against a red commit, because each G2 step starts after the G1 green commit it names (STATE carry-over (d): a sibling lane never waits on a throwing stub).

## Failure modes

| Step | What breaks | How I notice (the concrete signal) | How I back out |
|------|-------------|------------------------------------|----------------|
| 0 | the label takes no new image per frame, or frames tear | fewer than 20 distinct captures per second in the spike, or a capture mixing two frames | apply ADR 0071 §8: Reduce Motion presentation for everyone; strike the motion expectations with the reason |
| 0 | the widened item leaves the screen | the item window's bounds fall outside the screen at 180 points | the window becomes 120 points (ADR 0071 §8); re-run the spike once |
| 0 | the spike disturbs the owner | a ribbon longer than 10 s, or more than three runs | stop the scratch app (`kill` by its pid); no repository change to revert |
| 2 | a stored cadence the app does not know shows a ribbon | `RibbonPreferenceTests` `weekly` case red | the `cadence` getter returns nil; never a default |
| 6 | a DST night returns nil or the same instant twice, and the coordinator spins | `RibbonScheduleTests` DST cases red; in the app, a burst of `refresh` waits in the log | use `.nextTime` and compare strictly after the instant |
| 8 | the longest ribbon outlasts "a few seconds" | the 9.5 s bound test red | lower `stripMaxWidth`; the bound test stays |
| 12 | the app's own completion shows a ribbon | the local-completion case of `AppModelTests+Ribbon` red | compare against the board before the merge, which already holds the local write |
| 12 | the first pull after launch or a workspace switch shows a ribbon | the first-pull and from-start cases red | keep the `isPulledBefore` and `isFromStart` guards |
| 14 | a held ribbon shows twice after a Focus, or a ribbon keeps drawing after the gate turns quiet | the release-once and quiet-mid-ribbon cases red | claim the release once; cancel `running` on quiet |
| 14 | an agent burst shows several ribbons | the settle and cooldown cases red | one settle task, replaced on each call |
| 17 | the ribbon text is dimmed by the day temperature, or the glyph moves | renders: the text alpha below 1 at hold, or the glyph's columns differ from the count image's | draw the ribbon from its own image path, never through `MenuBarCountImage` |
| 17 | a frame re-renders the strip | Instruments or a counter: `ImageRenderer` called more than once per ribbon | cache the strip per content in the label |
| 18 | the popover anchors to the wide item | the popover's arrow off the glyph after a click mid-ribbon | `end()` on the panel's show, before it anchors (step 0 measured it) |
| 16, 18 | a merge with `focus-switch-defaults`, `day-email` or `siri-shortcuts` loses a row or a start call | the merged `SettingsView` lacks a row, or `xcodebuild` fails | the lead merges by hand, keeping both sides; never rebase |

**Steps with no backout:** none. Every step is code or docs on the branch; the spike leaves nothing in the repository; the two defaults keys are inert when the code is gone.
