## Edge cases found during execution

Walked at c4584899 on a local `wrangler dev` with the limits set through the `FAIR_USE_*` vars. Playwright MCP was down (its browser is not installed), so the admin walk was scripted with Playwright driving system Chrome, in light and dark at 1280 and 375.

- DEFECT 1 (IMPORTANT) The owner API refuses notes over about 4 KB: the body bound `BODY_LENGTH_MAX` in `apps/api/src/request-body.ts` is 4,096 bytes, but notes may be 10,240 bytes. With default limits, `POST /owner/projects/:id/tasks` with 4,096, 5,000 and 10,240 bytes of notes answered 400 `{"error":"invalid_request"}` (3,000 and 4,000 answered 201), and `PATCH` of 10,240 answered 400 too. Over MCP the same sizes were accepted and 10,241 was refused with "The notes are longer than 10 KB." So the app (owner API) cannot store a note the docs promise (`apps/docs/fair-use.mdx`: Notes 10 KB), and A-5 (10,240 ASCII bytes accepted) fails over the owner API. A-5 and A-7 are left unticked. Regression test wanted: an owner API add with 10,240 bytes of notes answers 201 and with 10,241 answers 422 `notes_too_long`.
- DEFECT 2 (MINOR) The admin usage page overflows horizontally at 375 px: `scrollWidth` 422 against `clientWidth` 375; the Action column (Suspend and Restore) is clipped and needs a sideways scroll. Screenshots: `docs/features/fair-use/admin-top-usage-light-375.png`, `admin-top-usage-dark-375.png`. At 1280 there is no overflow (`admin-top-usage-light.png`, `admin-top-usage-dark.png`).
- NOTE (cosmetic) The stored-bytes sentence prints the cap as a raw fraction of a MB when a self-host sets it in small byte counts (cap 3000 reads "0.00286102294921875 MB"). Defaults print "50 MB". Not a defect at defaults.
- Task changes only count task writes (add, update, complete, reopen). Creating workspaces, projects and keys, and renaming, do not use the daily count (30 renames never hit a cap of 12). Matches `apps/api/src/owner-task-writes.ts`; worth saying in the docs table if "Task changes per day" is meant literally.
- G-1, G-2, G-6 cannot be walked locally: the sign-up cap is skipped when the public origin and request are local, and a non-local host needs a real Turnstile siteverify. They stay with `apps/api/test/owner-sign-up-limits.test.ts`.
- Not run in this walk: C-1 to C-8, E-6, X-2, X-3, A-1, A-2, A-7, A-8, B-1 to B-3, I-1, I-2 (storage and unit level, or outside the lighter gate).
- The shared worktree's `HEAD` moved to e7acfbc6 and later during the run, so the servers were rebuilt from a frozen checkout of c4584899 for the MCP, notes and sign-up passes.
