# Plan: Mac sync

**Spec:** spec.md
**Tier:** 🔴
**Seam:** `apps/macos/TodzKit` (new cache, outbox, overlay, feed cursor and socket units; `AppModel` routes task writes through the outbox and gains the cache and the watchers) and `apps/macos/Todz` (the sync status item, pending rows, the refused notice, the sign-out confirmation, injection of the store and the sockets). Nothing outside `apps/macos` changes but this folder's docs and `AGENTS.md`'s shared-helper line.
**Assumptions (decided, owner can override):**
- ADRs 0027 to 0029 and `design.md` § 7 are the loop's calls, listed in the loop's questions. No third-party Swift dependency.
- Swift 6 language mode, strict concurrency, Swift Testing, `swift test` from `apps/macos/TodzKit`, as in the shell's plan; its convention bullets hold here word for word (no comments but `// NB ADR NNNN:`, no `??` default, flat `guard`s, enums over literals, file-top `private let lowerCamel` constants, labels, array methods, no acronyms). A default parameter value at a signature is allowed (`AGENTS.md`).
- Every cached shape is encoded with `OwnerCoding.encoder()` and decoded with `OwnerCoding.decoder()`, so a cache file looks like an owner API answer (snake_case, dates as epoch milliseconds).
- Tests never touch the real container: `FileSyncStore` takes its folder; tests pass a temporary folder.
- Waits go through an injected `pause: @Sendable (Duration) async throws -> Void`. Production passes `Task.sleep(for:)`; tests pass `HeldPause`, which records the durations and suspends until the test releases it. No test waits on the clock.
- Files are written with the Write and Edit tools: `guard-secrets.sh` blocks code heredocs and any shell line with an expansion.
- Red-first as in the shell: each red commit holds the failing test alone, plus stubs that `fatalError("<name> is not implemented")` and the types the test compiles against; its body records the failure the red run printed. A test that is green when it lands is a `pin`.
- Every lane leaves `swift test` and the app build (`xcodegen generate` then `xcodebuild build`, as the `macos` gate runs them) green at its last commit.

## Sequencing

1. G0 runs first on `feat/mac-sync` (one red and one green commit), because G1a's model coding and G1b's `PendingChange` dates both rely on its date strategy.
2. G1a and G1b then run in parallel, one worktree each, branched from `feat/mac-sync` at G0's head; neither touches the other's files. G1b's `TaskViews` takes `pendingTasks` as a defaulted last-but-two parameter, so `AppModel.swift` and `Todz/MainWindow/TaskList/TaskListState.swift` compile unchanged.
3. The lead merges G1a, then G1b (merge, never rebase), runs `swift test` and the app build, and hands G2 to `developer-model` on the merged branch.
4. G2 keeps every property and method the views read today (`writesInFlight`, `pullsInFlight`, `unconfirmedDrafts`, `isSaving`, `isWriting`, …) compiling, even where they become always empty; G3 deletes their last uses and G2's leftovers are removed in G3's step 21. G2 changes the one `AppModel(…)` call in `TodzApp.swift`, injecting `FileSyncStore`, `SocketChangeSignals` and the production pause.
5. G3 starts after the lead merges G2.
