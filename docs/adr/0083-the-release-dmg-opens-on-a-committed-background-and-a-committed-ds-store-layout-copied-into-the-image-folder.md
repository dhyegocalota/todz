# 0083. The release DMG opens on a committed background and a committed .DS_Store layout, copied into the image folder

- Status: Accepted
- Date: 2026-11-26
- Deciders: Claude (the build loop's call); Dhyego Calota (owner) may overturn it
- Inspired by: [ADR 0072](0072-the-mac-app-downloads-from-todz-app-as-a-development-signed-dmg-with-an-ssh-signature-and-updates-through-sparkle.md) decision 2, `scripts/release-mac.sh` (`create_disk_image`)

## Context

The release DMG is a bare folder of the app and an `Applications` link. The owner wants it to open on a branded window: the Liquid Glass look (`#0E1020`, `#4C6BFF` to `#1B2A9E`, mint `#8CF7D0`) with an arrow from Todz.app to Applications. Finder keeps a window's size, icon size, icon positions and background picture in the volume's `.DS_Store`. The release command runs unattended, tests with fakes and has no Accessibility permission.

## Decision

1. The layout is a `.DS_Store` committed in `apps/macos/release/`, generated once on a throwaway image, and copied with the background into the staging folder that `hdiutil create -srcfolder` already packs. No read-write image, no mount and no Finder session at build time.
2. The background is `apps/macos/release/dmg-background.svg` (source) and `dmg-background.tiff`, a multi-representation TIFF of the 1x and 2x renders (`tiffutil -cathidpicheck`), copied to `.background/dmg-background.tiff`. The icon labels sit on mid-blue plates so Finder's black label in light mode and white label in dark mode both stay readable.
3. A missing background or layout file refuses the release with a named message before `hdiutil` runs. The image stays UDZO and is signed as before; the sum, signature and appcast steps do not change.

## Alternatives considered

| Option | Pros | Cons | Why not |
|--------|------|------|---------|
| Committed `.DS_Store` (chosen) | Deterministic; no GUI, no Accessibility; testable with the fakes | Binary file; regenerated by hand when the layout changes | — |
| Finder AppleScript at build time | Layout lives in text | Needs a GUI session and Accessibility permission; timing flaky; opens windows in front of the owner; fakes cannot test it | Fails the unattended release |
| Python `ds_store` at build time | Deterministic | A new build dependency on the release Mac | Committed output has the same effect without it |

## Consequences

- The release command's staging folder gains `.background/` and `.DS_Store`.
- A layout change is a new `.DS_Store` generated by the recipe in Evidence, committed with its background.

## Evidence

Generated in a scratch virtual environment with `ds_store` and `mac_alias` on a mounted throwaway image; recorded in the pull request.

## Revisit when

- Finder stops honouring a copied `.DS_Store` or the alias to the background.
- The DMG layout needs more than the two icons.
