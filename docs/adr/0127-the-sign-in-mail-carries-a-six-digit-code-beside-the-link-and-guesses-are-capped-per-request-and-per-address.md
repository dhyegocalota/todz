# 0127. The sign-in mail carries a six digit code beside the link, and guesses are capped per request and per address

- Status: Accepted (the loop's call)
- Date: 2026-11-27
- Deciders: Claude (the build loop's call, under the owner's order of 2026-11-27 that every sign-in mail carry a code beside the link, "espaçado, bonito, ctrl+v automático dá enter")
- Inspired by: [0040](0040-the-owner-signs-in-with-an-email-link-bound-to-the-mac-that-asked-for-it.md), [0051](0051-the-admin-signs-in-by-a-mail-link-bound-to-the-browser-that-asked-into-a-cookie-session.md), [0109](0109-mcp-clients-connect-with-oauth-2-1-pkce-and-dynamic-registration-and-a-grant-is-never-more-than-the-equivalent-key.md)

The loop's call: the one sign-in mail of the app, of the OAuth browser sign-in and of the admin carries the link and a six digit code, either signs in, and using one spends both because the code sits on the link's row (a keyed digest with a per-row random salt, compared through `isSameSignature`, never stored or logged in clear) and shares its fifteen minute life, its single use and its binding to the request that asked: the `link_verifier` for the app, the challenge cookie for the OAuth and admin browsers. A guess is reserved in one statement before it is compared, so parallel guesses cannot outrun the caps: five misses on one request spend that request's link and code, ten misses per address in 24 hours lock code sign-in for that address (the link keeps working), and a per-client limiter on code attempts answers `429 code_locked` with `Retry-After` like both caps; misses are counted by the digest of the address and the request alone, so an address that never asked answers and locks exactly like one that did. The brute-force math: a code is one of 10^6 values drawn uniformly, so one guess wins with probability 10^-6; the address cap allows at most 10 guesses a day, a chance of 10^-5 (0.001%) per day and 1 - (1 - 10^-5)^365, about 0.36%, per year against one address, and only an attacker who first asks for the codes in the victim's inbox (five mails per 15 minutes, which the victim sees) and who never trips the per-client limiter can try at all; without the address cap, one client at its limit of 10 guesses a minute would make 14,400 a day, about 1.4%, and every extra client address multiplies that. An eight digit code (10^-8 per guess) was the alternative and the owner asked for six boxes; the cost of the address cap is that anyone can lock code sign-in for an address by missing ten times, which the link path survives and the owner reads as "use the link in the email".
