## Context

`todz.app` is two pages rendered by the Worker at module load (`/` and `/self-host`), under a strict CSP built from SHA-256 hashes of the one inline style and the one page script, with Turnstile on the waitlist form. It has a title, a description, `lang` and `theme-color` for both schemes, and nothing else a crawler, an answer engine or a browser agent reads: no canonical, no Open Graph, no icons, no structured data, no `robots.txt` of its own, no `llms.txt`.

Lighthouse 13.6.0 on production, mobile, 2026-11-25 (Evidence) scores Performance 92, Accessibility 100, Best Practices 88, SEO 92 and Agentic browsing 50. Its failures: `/favicon.ico` 404; a console error and an Issues entry from Cloudflare's Web Analytics beacon, which the edge injects into the HTML and the CSP blocks; `image-aspect-ratio` on the dark window shot inside `<picture>`; `robots-txt` (the file is Cloudflare's managed content-signals preamble, comments only); `llms-txt`; `ard-schema`; a simulated First Contentful Paint of 2.7 s for an 11.6 KB document with a 40 ms server response.

The owner names `navigator.modelContext` and `/.well-known/mcp/server-card.json`. Both have moved since he last read them:

- **WebMCP.** The Draft Community Group Report of 24 November 2026 exposes `ModelContext` as `document.modelContext` (`partial interface Document { [SecureContext, SameObject] readonly attribute ModelContext modelContext; }`), not on `Navigator`. A page registers a tool with `registerTool(tool, { signal })`; a tool is `{ name, title?, description, inputSchema?, outputSchema?, execute(input, { signal }), annotations? }`, the annotations being the booleans `readOnlyHint`, `untrustedContentHint`, `consequentialHint` and `debugging`. Chrome's guide (updated 20 November 2026) requires an `inputSchema` and says `consequentialHint` lets agents and browsers enforce a confirmation before high-stakes tools. Registration is secure-context only, per document, and off in cross-origin frames unless the `tools` Permissions Policy allows it; other origins see a tool only when it lists them in `exposedTo`. Chrome runs an origin trial from 149 and takes `about:flags#enable-webmcp-testing` for local work; Edge has an origin trial from 150; Firefox and Safari have none. The declarative form variant (`toolname`, `tooldescription`, `toolautosubmit` on a `<form>`) is an exploratory explainer, not in the draft.
- **Server cards.** SEP-2127 "MCP Server Cards" is Final (created 2026-01-21). Its normative schema (`experimental-ext-server-card`, `schema.ts`) requires `$schema` (`https://static.modelcontextprotocol.io/schemas/v1/server-card.schema.json`), `name` (reverse DNS with one slash), `version` and `description` (1 to 100 characters), and allows `title`, `websiteUrl`, `repository`, `icons` and `remotes` (`type` `streamable-http`, `url`, `headers`, `supportedProtocolVersions`). Tools, capabilities and authentication are excluded on purpose, because primitives vary per user. The recommended location is `<streamable-http-url>/server-card`, the media type `application/mcp-server-card+json`, with `Access-Control-Allow-Origin: *` and `Cache-Control: public, max-age=3600`; domain discovery goes through a catalog, not through a card under `.well-known`. Lighthouse 13.5 audits that catalog as ARD v0.91 (Agentic Resource Discovery, a proposal dated 26 August 2026) at `/.well-known/ard.json`: `entries`, each with an `identifier` of the form `urn:air:<publisher>:<name>`, a `displayName`, a media `type` and exactly one of `url` or `data`, with two to five `representativeQueries` recommended; it calls `ai-catalog.json` the deprecated name.
- **`llms.txt`.** llmstxt.org: an H1 with the name (the only required part), a blockquote summary, optional prose, then H2 sections of `- [name](url): notes` lists, with an `Optional` section an agent may skip. `llms-full.txt` has no specification; it is the convention of one file with the full text (Mintlify generates both for its sites).

## Decision

1. **Every public page carries its own head from one shell.** `SiteDocument` is discriminated by kind: a public page (`/`, `/self-host`) gives its path and gets the tags below; a private page (the admin and its link page) gets the title, the favicon links and nothing else a crawler or a share preview reads. For a public page, `siteDocumentHtml` writes the title, the description, a canonical URL on `https://todz.app`, `og:title`, `og:description`, `og:url`, `og:type` (`website`), `og:site_name`, `og:image` with its width, height and alt, `twitter:card` `summary_large_image`, the icon links, the manifest link and the existing `lang` and `theme-color` pair. The absolute URLs come from one module of production URLs (`https://todz.app`, `https://api.todz.app/mcp`, `https://docs.todz.app`): these documents describe the product, not a deployment, so they never vary with `SITE_ORIGIN`.
2. **JSON-LD is one `@graph` per public page, hashed into the CSP.** A `<script type="application/ld+json">` holds `Organization` (Logic Bit, from `COMPANY`, with `logo` the studio's own 180-pixel icon at `https://www.logicbit.com.br/favicon/apple-touch-icon.png`), `WebSite` (todz.app, its publisher the organization) and, on the landing, `SoftwareApplication` (todz, `operatingSystem` macOS 14 or later, `applicationCategory` `BusinessApplication` with `applicationSubCategory` `Productivity`, its publisher the organization, one `Offer`). Its exact bytes are hashed into `script-src` like the page script. A data block never runs and browsers do not hold it to `script-src`, so the hash buys no execution; it is kept because the owner asked for JSON-LD "with a hash or nonce", and because a policy that names every inline `<script>` the page writes lets one test prove the page's whole inline surface is known, with no `'unsafe-inline'` anywhere. No inline event handler exists or is added.
3. **The discovery files are Worker routes on the site host, built from the copy modules.** `robots.txt`, `sitemap.xml`, `llms.txt`, `llms-full.txt`, `site.webmanifest`, `/.well-known/ard.json` and `/.well-known/mcp/server-card.json` are fixed strings built once at module load from `LANDING_COPY`, `MCP_COPY` and one agent-setup module whose three commands match `AgentCommand.swift`, so the MCP tool list and the `claude mcp add` line cannot drift from what the app and the server say. They are not files under `apps/api/public` because a static asset answers on every host, `api.todz.app` included, and because a file copied from the copy is a second source.
   - `robots.txt` allows every agent, names the search and AI crawlers (`Googlebot`, `Bingbot`, `GPTBot`, `OAI-SearchBot`, `ChatGPT-User`, `ClaudeBot`, `Claude-SearchBot`, `Claude-User`, `PerplexityBot`, `Perplexity-User`, `Google-Extended`, `Applebot-Extended`) with `Allow: /`, and lists two sitemaps: the site's and `https://docs.todz.app/sitemap.xml`, because a sitemap may only list URLs of its own host while `robots.txt` may point at another host's sitemap.
   - `sitemap.xml` lists `https://todz.app/` and `https://todz.app/self-host`.
   - `llms.txt` follows llmstxt.org: `# todz`, a one-line blockquote, short facts (what it is, status, pricing, the publisher), then `## Connect an agent` (the Claude Code line, the Codex and Cursor setups by link), `## MCP tools` (each tool's name and description from `MCP_COPY`), `## Docs`, and `## Optional`. `llms-full.txt` is the same file with the three setups in full and each tool's parameters.
4. **The server card lives where SEP-2127 recommends it, and where the owner asked.** One card (`name` `app.todz/todz`, the server's own version, `remotes` with the streamable HTTP URL `https://api.todz.app/mcp`, an `Authorization` header marked required and secret, and the SDK's supported protocol versions) is served with the same bytes at `https://api.todz.app/mcp/server-card` and at `https://todz.app/.well-known/mcp/server-card.json`, as `application/mcp-server-card+json`, with open CORS for `GET` and `Cache-Control: public, max-age=3600`. `https://todz.app/.well-known/ard.json` lists it under `urn:air:todz.app:mcp:todz` with three representative queries. The card lists no tools, as the SEP requires; the tool list lives in `llms.txt` and in `tools/list` behind a key.
5. **WebMCP is imperative, on the landing only, behind feature detection.** One fixed script, hashed into `script-src`, finds `document.modelContext`, else `navigator.modelContext` for the implementations and polyfills that still use the old name, and returns when neither exists. It registers four tools, their names, descriptions and schemas from a copy module:
   - `get_todz_overview` (`readOnlyHint`): what todz is, its status, its pricing and its links, the same facts as `llms.txt`;
   - `get_mcp_setup` (`readOnlyHint`), input `{ client: "claude-code" | "codex" | "cursor" }`: the setup for that client with `<key>` in place of the key, and where the key comes from;
   - `open_docs` (`readOnlyHint`), input `{ page: "introduction" | "quickstart" | "connect-an-agent" | "mcp-tools" | "self-host" }`: navigates the tab to that page of `https://docs.todz.app`; the enum and `llms.txt`'s docs links read one page list, pinned to the pages under `apps/docs` once `docs-mintlify` has landed;
   - `join_waitlist` (`consequentialHint`), input `{ email }`: answers "already submitting" when the first form's button carries `aria-disabled="true"`, puts the address in the form's field and answers "invalid" when the field's own validity refuses it, and otherwise calls `requestSubmit()` on the form, so the page's own submit handler waits for the Turnstile token the widget obtains, and the browser posts the same `POST /join` with `cf-turnstile-response`. It then answers that the form was sent and the page will show the result. It never calls `fetch`, so `connect-src` stays absent, and the server's Turnstile check, the three limits and the alike answer for every address (ADR 0050) are unchanged: **no bypass and no new unauthenticated path**.
6. **Icons and the Open Graph image are generated from `docs/brand` and committed.** `docs/brand` holds byte copies of `todz-loop/brand` (ADR 0038). A script renders, with the Playwright Chromium the repository already pins, `favicon.ico` (16, 32 and 48 pixel PNG entries in one ICO container written by a small encoder, each cropped to the squircle so no transparent margin wastes the few pixels), `icon.svg` (the brand icon with a `prefers-color-scheme: dark` rule that lifts the gradient for dark tab strips), `icon-192.png` and `icon-512.png`, their maskable twins and `apple-touch-icon.png` (180) (the brand gradient full-bleed with the check and spark at about 80 % of the side, because iOS masks the touch icon itself and fills transparency with black), WebP copies of the landing shots at their displayed widths, and `og/todz.png` (1200 × 630: the owner's lockup render and a real app shot). Rendering needs a browser, so the gate never renders: `generate` writes the outputs and a committed lock file of SHA-256 hashes of every input (`docs/brand/*`, the landing shots it reads, the two constant modules it reads (`site-icons.ts`, `landing-shots.ts`), the generator's own source files), and `check`, run by a node unit test, compares the lock with the inputs on disk and fails with the regenerate command when one changed. The outputs are proven by size, format and pixel rules on the committed files.
7. **The policy and headers allow exactly this.** The site CSP gains `manifest-src 'self'` and the hashes of the JSON-LD block and the WebMCP script; everything else stays `'none'` or `'self'`. Site pages send `Cache-Control: no-cache, no-transform`: `no-transform` stops Cloudflare from injecting the Web Analytics beacon the CSP already blocks, which is the console error Lighthouse counts.
   - If the beacon survives `no-transform` on production, or production `robots.txt` carries Cloudflare's managed preamble with directives (a `User-agent`, `Disallow` or `Content-Signal` line, not only comments), the zone settings behind them are turned off: the managed `robots.txt` and content signals (`/zones/<zone>/bot_management`) and Web Analytics' automatic setup. The loop does it through `scripts/todz-cloudflare.sh` when the wrapper's allowlist covers the path and the token's permission covers the setting, as it did for Always Use HTTPS (PROMPT.md authorizes `todz.app` zone settings); otherwise it is an owner step in the dashboard. The deploy runbook carries the check and both branches.
8. **Scores are measured, not assumed.** Lighthouse `13.6.0`, run with `pnpm dlx` on the Chromium that `@playwright/test` installs, on a phone profile, records Performance, Accessibility, Best Practices, SEO and Agentic browsing on `wrangler dev` before the pull request and on production after the deploy, three runs per URL, the median kept. Acceptance is on production: SEO, Best Practices and Accessibility 100 and Performance 95 or more (the owner's targets), and every Agentic browsing audit on the landing green. A production Performance under 95 after the deploy opens a follow-up fix pull request, named in the plan, rather than holding this one.

## Alternatives considered

| Option | Pros | Cons | Why not |
|--------|------|------|---------|
| WebMCP imperative on `document.modelContext`, old name as a fallback (chosen) | in the draft; one hashed script; `join_waitlist` reuses the form and its token | Chrome stable needs the origin trial or the flag | — |
| WebMCP declarative (`toolname` on the join form) | no script; the browser fills the form and the person submits | not in the draft, an exploratory explainer; read-only tools have no form; two join forms would make two tools | not standard yet; revisit when it lands in the draft |
| `navigator.modelContext` only, as the owner wrote it | what the owner named | the draft and Chrome moved it to `document` | it would register nothing in a current browser |
| A `join_waitlist` that posts with `fetch` | returns the server's answer to the agent | needs `connect-src 'self'`; a second client of `/join`; an agent could call it without the widget | the owner's rule: no new path, the page obtains the token |
| Server card at `/.well-known/mcp/server-card.json` only | the owner's path | not where SEP-2127 recommends a card; `.well-known` is for site-wide metadata | served there too, beside the recommended `/mcp/server-card` |
| No server card | nothing to keep in step | no pre-connection discovery for registries and IDEs | the owner asked for one |
| `ai-catalog.json` as the catalog | the name in SEP-2127's text | Lighthouse 13.5 audits ARD and calls it deprecated | ARD at `/.well-known/ard.json` |
| Discovery files as static assets in `apps/api/public` | no Worker code | answered on `api.todz.app` too; a second copy of the copy that drifts | Worker routes from the copy modules |
| Absolute URLs from `SITE_ORIGIN` | right for any deployment | a self-host or local run would publish its own origin as todz's canonical | the files describe todz.app |
| Icons rendered by hand with `rsvg-convert` and `magick` (the brand runbook's tools) | known output | not in the gate; tools outside the repository | the pinned Playwright Chromium renders, and a lock of input hashes proves the files current |
| A check that renders again and compares bytes | proves the outputs, not only the inputs | a browser in the unit gate; renders can differ between machines | the lock of input hashes, plus size and pixel rules on the committed outputs |
| A transparent-cornered `apple-touch-icon` like the favicon | one look everywhere | iOS fills transparency with black and masks the corners itself | full-bleed, like the maskable icons |
| Allow the Cloudflare beacon in the CSP | analytics in the dashboard | a third-party script origin in `script-src`; a host allowlist Lighthouse flags | `no-transform`; analytics can come later as a hashed snippet the owner asks for |
| `SoftwareApplication` with an `aggregateRating` | eligible for Google's rich result | there are no ratings; inventing them is fabrication | omitted; the rich result waits for real reviews |

## Consequences

- WebMCP tools reach an agent only in a browser that exposes `document.modelContext` (Chrome with the origin trial or the flag, Edge's trial, the polyfill, browser agents that inject it). Joining the origin trial for `todz.app` is an owner step; until then the tools are inert in Chrome stable and nothing breaks.
- A browser agent can fill the waitlist but cannot pass Turnstile for the person: when the widget asks for interaction, the person solves it, as on any visit.
- The `SoftwareApplication` offer says what is true today: joining the waitlist costs nothing (`price` `0`, `USD`, `PreOrder`, linking `/#join`). When pricing exists, the offer, `llms.txt` and the overview tool change together, because they read one copy entry. Without ratings Google shows no software rich result; the markup still names the app, its platform and its publisher.
- Every discovery file and the card are public, fixed and read-only; they hold no secret and no per-user data, and the card's header entry names the header, never a value.
- `robots.txt` invites training crawlers too, as the owner asked ("robots.txt allowing the AI crawlers"); a zone-level Cloudflare bot rule can still answer them 403, which the deploy run checks.
- `/self-host` stays in the sitemap until `docs-cutover` makes it a redirect; that feature removes it from the sitemap and `llms.txt` in the same change.

## Revisit when

- The WebMCP draft drops or renames `document.modelContext`, adds the declarative form variant, or Chrome ships it without the origin trial.
- SEP-2127's extension moves its schema URL or the recommended card location, or ARD leaves v0.91.
- todz gets a price, reviews or a public repository (the offer, `aggregateRating` and the card's `repository`). `PreOrder` with price `0` stands for the free waitlist only; it must change the day the app can be downloaded or bought.
- Logic Bit's site moves its icon (the `Organization.logo` URL).
- `docs-cutover` turns `/self-host` into a redirect.
